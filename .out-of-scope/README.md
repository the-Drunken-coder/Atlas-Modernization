# Out of scope knowledge base

`$matt-triage` records a rejected enhancement here only when the rejection is a durable product boundary worth checking before future triage. Each entry should name the rejected request, explain the boundary, and link to the GitHub Issue that recorded the decision.

Do not add already implemented requests, transient defects, or architectural decisions. Those belong in the codebase, `docs/problems/`, or `docs/design-decisions/` respectively.
