1. **Time & Date:** 2026-09-18T15:00:56Z
2. **Name:** Sync engine concentrates six hand-correlated invalidation tokens in a 984-line file; explicit state machine is the proposed (not mandatory) remedy
3. **Issue:** `sync-engine.ts` coordinates six independent staleness/invalidation tokens by hand across dozens of `isCurrent*` checks. The code passes its tests, but this file is the system's plausible future-defect concentration: every reconnect/recovery/hydration interleaving must be manually correlated against every token instead of being checked against a small explicit state set.
4. **Severity:** S4 (not a defect — tested and currently correct; risk concentration that makes future changes error-prone and review expensive)
5. **Location:** `packages/sdk/src/sync-engine.ts` (984 lines); helpers `packages/sdk/src/sync-engine-lifecycle.ts` (48 lines), `packages/sdk/src/sync-engine-recovery.ts` (113 lines), `packages/sdk/src/sync-engine-reconnect.ts` (23 lines)
6. **Expected:** For reviewability: a small enumerated state set (`idle`/`starting`/`hydrating`/`recovering`/`connected`/`reconnecting`/`stopped`), explicit transitions between them, and a single authoritative generation token whose cancellation propagates automatically to child operations — making invalid code paths structurally impossible rather than requiring a fresh `isCurrent*` check at every await point.
7. **Actual:** Six independently incremented tokens, correlated by hand at each continuation point:
   - lifecycle generation — `SyncLifecycle.generation` (`sync-engine-lifecycle.ts:2`, bumped in `beginStart` :11 and `stop` :15)
   - feed-connection attempt — `SyncLifecycle.feedConnectionAttempt` (`sync-engine-lifecycle.ts:3`, `beginFeedConnectionAttempt` :24; combined check `isCurrentFeedConnection` :31-33)
   - recovery operation — `RecoveryCoordinator.operation` (`sync-engine-recovery.ts:9`, bumped in `invalidate` :23; `RecoveryRunner.run` re-checks it around every page :73, :79, :92)
   - hydration epoch — `SyncEngine.activeHydration` object identity (`sync-engine.ts:131`, type :59-63; identity compare :680, :688; its `ActiveHydration.operation` field :61 additionally couples hydration to token 3)
   - recovery buffer identity — `SyncEngine.feedRecoveryBuffer` object identity (`sync-engine.ts:132`, type :65-70; identity compares at :289, :808, :820, :825, :828)
   - reconnect pending — `ReconnectTimer.timer` truthiness (`sync-engine-reconnect.ts:4-8`), further correlated with two manual booleans `reconnecting`/`reconnectAfterRecovery` (`sync-engine.ts:136-137`, set/cleared at :185-186, :622-623, :746-751, :831-833, :841-842) and `AutomaticReconnectOwnership.recoveryOperation` (`sync-engine.ts:55-57`)
