1. **Time & Date:** 2026-09-18T15:00:56Z
2. **Name:** Source Gateway's single 1,125-line file carries a ~320-line bespoke circuit breaker sized for a scale of one external connector
3. **Issue:** All Source Gateway request handling, caching, rate limiting, egress validation, and a fully custom circuit breaker live in one file (`gateway.go`, 1,125 lines), of which roughly 28% is breaker machinery — while the deployment ships only two connector fragments (one real external source), so the most intricate part of the file protects a single flaky-public-API connection today.
4. **Severity:** S5
5. **Location:** `services/core/internal/sourcegateway/gateway.go` (fields `gateway.go:54-92`, breaker methods `gateway.go:733-924`, breaker integration in `execute()` at `gateway.go:346-350,371-376,378-396,407-472`, completion recording at `gateway.go:568,583,592`), `plugins/building_scan/source-connector.json`, `plugins/reference/source-connector.json`, `services/core/go.mod`
6. **Expected:** The breaker's complexity should be proportional to the number and criticality of external connections it protects, and the file should be small enough that the breaker, cache, rate limiter, and HTTP handling are individually reviewable; if bespoke breaker state (credit groups, completion-serial ordering, history compaction, fail-closed history limit) is kept, that choice should be justified against the current connector population.
7. **Actual:** `gateway.go` holds 1,125 lines in one file. Breaker-dedicated code spans types/fields at `gateway.go:54-92` (`breakerSerial:60`, `breakerAttempts:64`, `breakerFailures:65`, `breakerCredits:66`, `lastReachable:67`, `breakerHistoryLimit:92` at 4,096 records) and ~192 lines of methods at `gateway.go:733-924` (`tryBeginAttempt`, `finishBreakerFailure`, `finishBreakerReachable`, `expireBreakerLocked`, `settleExpiredBreakerGroupsLocked`, `creditedFailureCountLocked`, `recomputeBreakerLocked`, …), plus ~90 more lines wiring it into `execute()`. That is ≈320 lines (≈28% of the file) implementing credit-group accounting, ordering by completion serial, unresolved-attempt blocking of compaction, and fail-closed history bounds. Meanwhile the configured connector population is two: `plugins/building_scan/source-connector.json` (the only external origin, `https://overpass-api.de`, max_concurrency 1, 0.2 rps) and `plugins/reference/source-connector.json` (a local Compose fixture at `reference-source:8090`); the committed base settings contain no connectors (`services/core/docs/SOURCE_GATEWAY.md:65`).
8. **Reproduction:** (a) `wc -l services/core/internal/sourcegateway/gateway.go` → 1,125 lines in one file. (b) Read `gateway.go:54-92` and `gateway.go:733-924`: the connector struct carries six breaker fields plus four breaker types, and sixteen breaker methods implement a credit/compaction/ordering scheme well beyond a count-failures-open-countdown-reset breaker. (c) `ls plugins/*/source-connector.json` → exactly two fragments; the only external one targets `https://overpass-api.de`. (d) `grep -n "require" services/core/go.mod` shows no breaker library (no sony/gobreaker, no gobwas) — the implementation is entirely hand-rolled. (e) `grep -n "^func Test" services/core/internal/sourcegateway/gateway_test.go | grep -iE "breaker|circuit"` → 14 dedicated tests; breaker/circuit references span lines 66-1602 of the 1,938-line test file, so the machinery is thoroughly exercised.
9. **Notes:** Fairness check: the breaker is not gratuitous — the Plugin contract mandates a per-connector breaker with a fixed `circuit_open` 503 (`docs/atlas-plugins/README.md:232`) and "one circuit breaker per connector" (`docs/atlas-plugins/README.md:256`), and the sole external connector is Overpass API, a shared public endpoint that rate-limits and degrades, so breaker semantics have a genuine failure-mode target. It is also heavily tested (14 dedicated tests of 51). However, no off-the-shelf library is present in `services/core/go.mod`, so the bespoke implementation was a deliberate choice rather than a constraint, and its advanced features (credit groups expiring per open interval, completion-serial tie-breaking, 4,096-record fail-closed history) address concurrency and pathological-transport scenarios that a one-connector deployment has not demonstrated. Verdict framing: this is working, tested code and the severity reflects a scale mismatch / premature generality observation, not a defect. This report covers only in-file size and bespoke-breaker complexity versus current scale; the separate question of the Gateway's module/ownership boundary inside `services/core` is documented in `docs/problems/2026-09-18-source-gateway-module-boundary.md` and is not duplicated here. Any remediation belongs to the maintainer (splitting the file and/or simplifying the breaker); this report only records the finding.
