# Problem Report

1. **Time & Date:** 2026-08-30T14:58:14Z
2. **Name:** FieldLink node close can block forever on a built-in reply
3. **Issue:** `FieldLinkNode.close()` waits for every active message callback before closing its frame scheduler, but the built-in `context.reply()` sends without an abort signal. A reply waiting for a permanently non-shallow transport queue can therefore prevent node shutdown indefinitely.
4. **Severity:** S3 (Moderate)
5. **Location:** Atlas FieldLink, `packages/fieldlink/src/node.ts` (`FieldLinkNode.close`, built-in message-handler context, and `FrameScheduler`)
6. **Expected:** Once `close()` is requested, the node should reach a terminal shutdown state and close the transport even when an inbound handler is waiting to send a reply that cannot progress. A blocked reply should be cancelled or otherwise bounded by the node's shutdown path.
7. **Actual:** `#close()` marks the node closing and aborts `#receiveController` at lines 601–604, then waits indefinitely in `settleUntilEmpty(this.#activeCallbacks)` at lines 606–608. The built-in handler context at lines 1505–1518 calls `this.send()` without `signal`, so a reply enters `FrameScheduler` without cancellation. With a nonzero transport queue length, `#waitForShallowQueue()` at lines 1935–1944 loops forever because its signal is undefined. `#close()` never reaches `#scheduler.close()` or `#transport.close()` at lines 609–625.
8. **Reproduction:**
   1. From the repository root, run this in-memory probe; it injects the built-in Test request into a node whose transport queue never becomes shallow:

      ```sh
      node --import tsx --input-type=module --eval 'import { FieldLinkNode, parseNodeId } from "./packages/fieldlink/src/node.ts"; import { encodeFrame, FrameKind } from "./packages/fieldlink/src/frame.ts"; import { testMessage } from "./packages/fieldlink/src/messages/test.ts"; class T { listeners = new Set(); queueLength = 1; sent = 0; closed = false; send() { this.sent += 1; return Promise.resolve(); } getQueueLength() { return Promise.resolve(this.queueLength); } onDatagram(listener) { this.listeners.add(listener); return () => this.listeners.delete(listener); } close() { this.closed = true; return Promise.resolve(); } inject(datagram) { for (const listener of this.listeners) void listener(datagram); } } const source = parseNodeId("aaaaaaaaaaaaaaaa"); const destination = parseNodeId("bbbbbbbbbbbbbbbb"); const transport = new T(); const node = new FieldLinkNode({ nodeId: destination, transport }); transport.inject({ bytes: encodeFrame({ transmissionId: 1, kind: FrameKind.complete, source, destination, logicalId: 1n, messageType: 1, body: testMessage.encode({ type: "test", kind: "request", correlationId: 7, payload: new Uint8Array() }) }) }); await new Promise((resolve) => setTimeout(resolve, 25)); const close = node.close(); const result = await Promise.race([close.then(() => "closed", () => "rejected"), new Promise((resolve) => setTimeout(() => resolve("timeout"), 100))]); console.log(JSON.stringify({ result, sent: transport.sent, closed: transport.closed })); process.exit(0);'
      ```

   2. Observe `{"result":"timeout","sent":0,"closed":false}`. The built-in handler has entered `context.reply()`, but `close()` has not closed the transport after 100 ms. The probe exits explicitly because the scheduler's unbounded polling timer remains active.
   3. The focused FieldLink node suite still passes (`42` tests), including the existing accepted-async-listener close test, which releases the handler before awaiting close and does not exercise a permanently blocked reply.
9. **Notes:** The existing `FieldLinkNode` API exposes `signal` on caller-owned `send()` and `publish()` options, but `MessageHandlerContext` has no signal. The smallest safe repair needs to preserve the intended response behavior for handlers already accepted before close while ensuring shutdown can cancel or bound a reply blocked in the scheduler. Do not run this reproduction with hardware; the in-memory transport is sufficient.
