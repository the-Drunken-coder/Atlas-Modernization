1. **Time & Date:** 2026-09-18T15:00:56Z
2. **Name:** Authorization is binary (authenticated/not) and scoping retrofit touches three coupled subsystems — feed fan-out, full-dataset hydration, and the SDK cache model
3. **Issue:** The only authorization boundary is "holds a valid credential." Every managed API key authorizes every asset's task lifecycle, every connected client can subscribe to any event, and every browser session hydrates the entire dataset. Per-asset or per-operator scoping is not a middleware addition; it requires coordinated changes to Core feed delivery, the full-dataset query, and the SDK cache.
4. **Severity:** S4 (documented deliberate v1 posture with high multi-operator retrofit cost; no active vulnerability claim — see Notes)

6. **Expected:** For multi-operator/multi-asset scoping, authorization would need to be evaluated server-side at three coupled points: (1) the feed hub would need per-client server-authorized visibility rules applied during `Publish`/`matchesLocked`, since subscriptions are currently client declarations; (2) the full-dataset hydration endpoint would need scoping parameters so a client cannot fetch resources it is not entitled to; (3) the SDK cache model (`sync: "all"` single unscoped snapshot) would need to become scope-aware so the cache reflects an authorized subset rather than the whole dataset. Task-lifecycle scoping would additionally require binding a credential to an asset/runtime rather than the current claim-matches-binding check.
7. **Actual:** Authorization is deliberately binary in v1 (SECURITY.md:127): middleware accepts the bootstrap key or any active managed key, and every key is full-access. Three structural coupling points make scoping expensive later: (a) `Atlas-Runtime-ID` is a claim, not a credential — task_transition.go compares the caller-supplied header value for equality against the stored runtime binding (`runtimeID != boundRuntimeID`, lines 283-284 and 445-447); the claimant is authenticated only by holding any valid API key, so any key holder can drive any asset's task lifecycle by naming the runtime ID; (b) feed security at subscription level is client-declared: `Publish` fans each committed event to all clients and `matchesLocked` delivers per-event only to clients whose own subscriptions match — delivery is correctly subscriber-filtered, but nothing server-side authorizes what a client may subscribe to; (c) the command interface uses `sync: "all"`, which makes the SDK subscribe `{ filter: "all" }` and page the entire dataset (`/queries/full`) into a browser-resident cache on start.
8. **Reproduction:** Source trace — one managed API key can transition any asset's tasks: middleware.go:193 accepts any valid key; handler_task.go passes only the `Atlas-Runtime-ID` header; task_transition.go:283/445 accept any header equal to the stored binding. Feed trace — a client dials `/feed` (authenticated at connection, handler_feed.go:29-60), then sends `{"action":"subscribe","filter":"all"}`; hub.go:138-149 accepts the subscription and 240-247 routes every event to it. Hydration trace — data-source.ts:56 passes `sync: "all"`; sync-engine.ts:158 subscribes `filter: "all"` and 694-724 pages the full dataset into the cache.
9. **Notes:** This is documented, deliberate v1 behavior — SECURITY.md:127 states managed API keys are "full-access machine credentials in v1" — and this report does not claim an active vulnerability. The finding is the extensibility cost: adding per-asset or per-operator scope later is not a middleware change but a coordinated change to feed fan-out, the full-dataset query, and the SDK cache model. The resource-instance-token scheme (data-source.ts:182-280) is the current stand-in for ownership: the browser generates a random capability at create time, keeps it in localStorage (lines 312-365), and presents it as `Atlas-Resource-Instance-Token` (resource_instance_token.go:15) so the UI can delete the geofeature it created — an ownership model implemented in the client, workable for one operator but not extensible to two. Related but distinct reports: `2026-09-18-geofeature-delete-browser-token.md` (token-loss operability defect) and `2026-09-18-sdk-hydration-ignores-subscriptions.md` (unconditional hydration growth); this report covers the cross-cutting authorization-scoping architecture.
