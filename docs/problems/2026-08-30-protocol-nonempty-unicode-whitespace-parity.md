# Problem Report

1. **Time & Date:** 2026-08-30T15:04:36Z
2. **Name:** Go and TypeScript validators disagree on Unicode-only NonEmptyString values
3. **Issue:** The canonical `NonEmptyString` contract is implemented with different whitespace semantics by the Go Protocol validator and generated TypeScript predicates. Go's JSON Schema dependency treats `\S` as an ASCII-whitespace complement, while the TypeScript helper uses ECMAScript `String.trim()`. A Unicode-only whitespace value can therefore pass Core's object validation and be persisted, then make the same object response fail SDK validation.
4. **Severity:** S4 (Minor)
5. **Location:** `packages/protocol/schema/jsonschema/atlas.schema.json:1142-1145`, `packages/protocol/validator/validator.go:37-72`, `packages/protocol/generated/typescript/index.ts:800-802`, `services/core/internal/api/handlers/handler_object.go:31-48`, `services/core/internal/actions/object_actions.go:44-84`, `services/core/internal/models/models.go:242-257`, and `services/core/internal/serializers/serializers.go:112-165`
6. **Expected:** Core and generated SDK validators should agree on every Protocol value. An object create request containing a Unicode-only whitespace usage hint should either be rejected consistently or be accepted consistently and remain valid as an `ObjectResource` and `ObjectDetailResource` response.
7. **Actual:** With `"\u00a0"` (NO-BREAK SPACE) as a usage hint, the Go validator returns no errors for both `ObjectCreateRequest` and `ObjectBlob`, while the generated TypeScript predicates return `false` for `ObjectCreateRequest`, `ObjectResource`, and `ObjectDetailResource`. The Core HTTP path validates the raw request with `protocol.ValidateObjectCreateRequest`, copies `UsageHints` into the JSON blob, validates that blob with the same permissive Go implementation, inserts it, and serializes the original hint unchanged. An SDK request validator consequently rejects the response with `Atlas response failed validation`.
8. **Reproduction:**
   1. From `packages/protocol`, run a Go probe that calls `protocol.ValidateObjectCreateRequest(map[string]any{"object_id": "object-1", "usage_hints": []any{"\u00a0"}})` and `protocol.ValidateObjectBlob(map[string]any{"usage_hints": []any{"\u00a0"}})`. Both return `[]`. The same result occurs for U+1680, U+2000, U+2028, U+2029, and U+FEFF; ordinary ASCII space and tab are rejected.
   2. From the repository root, run:
      ```sh
      node --import tsx --input-type=module -e 'import {isObjectCreateRequest,isObjectResource,isObjectDetailResource} from "./packages/protocol/generated/typescript/index.ts"; const value="\u00a0"; const request={object_id:"object-1",usage_hints:[value]}; const resource={object_id:"object-1",path:null,content_type:null,type:null,size_bytes:null,usage_hints:[value],bucket:null,metadata:{created_at:"2026-06-12T12:00:00Z",updated_at:"2026-06-12T12:00:00Z",version:1}}; console.log(isObjectCreateRequest(request),isObjectResource(resource),isObjectDetailResource({...resource,extra:{}}))'
      ```
      Observe `false false false`. For comparison, replacing `value` with `"\u200b"` (ZERO WIDTH SPACE) prints `true true true`, confirming that this is specifically a cross-runtime whitespace-set difference rather than a generic Unicode-string rejection.
   3. Trace or exercise `POST /objects` with `{"object_id":"object-1","usage_hints":["\u00a0"]}`. `CreateObject` calls `decodeProtocolRequestBody` with `protocol.ValidateObjectCreateRequest` at `handler_object.go:37`; `ObjectActions.Create` stores `params.UsageHints` and calls `marshalValidatedJSONBlob(..., ValidateObjectBlob)` at `object_actions.go:56-64`; `GetUsageHints` preserves the decoded string at `models.go:242-257`; and `SerializeObject`/`SerializeObjectForList` emit it at `serializers.go:112-165`. The SDK's `objects.create` and `objects.get` paths use `isObjectDetailResource` through `HttpTransport.json`, so the returned payload is rejected by the TypeScript predicate.
9. **Notes:** The Go probe and TypeScript probe ran against detached HEAD `804bf32fa733ca582f931816f58cdb5aae218701`; no live database or destructive Core stack was started. The existing protocol validator and SDK suites pass because they lack a paired Unicode-whitespace conformance case. The smallest repair is to define one explicit Unicode-aware predicate in the canonical contract, update the Go validator and generated TypeScript helper from that source, and add shared request/resource cases for Unicode whitespace-only values while retaining rejection of ASCII whitespace-only values. Generated artifacts should be regenerated rather than edited directly.
