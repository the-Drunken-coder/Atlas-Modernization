1. **Time & Date:** 2026-09-18T15:00:56Z
2. **Name:** Auth rules enforced from three scattered sites (middleware path-text lists, `/feed` handler re-auth, `feed.Server` checks); the "new route quietly exposed" and "dev API open vs feed closed" sub-claims do not reproduce
3. **Issue:** Whether a route requires login is decided by hardcoded path strings in three different files instead of being declared with the route group: `CombinedAuth` matches text paths to skip auth (including a bare `r.URL.Path == "/feed"` literal), the `/feed` handler re-implements API-key and session auth and mutates `feed.ServerConfig` flags to carry the result, and `feed.Server` re-checks key configuration and origin. The original finding's two risk claims are overstated or wrong: a newly added route defaults to protected (global deny-by-default middleware), and with `ENABLE_API_AUTH=false` the normal API is not open — it 401s without a session exactly like `/feed`.
4. **Severity:** S4 (design/maintainability drift hazard in a security-relevant path; no runtime defect, exposure, or user-visible inconsistency reproduces today)
5. **Location:** `services/core/internal/api/middleware/middleware.go:29-41,116-128,175-215`; `services/core/internal/api/handlers/handler_feed.go:25-68,71-79`; `services/core/internal/feed/server.go:45-58,83-89,277-279`; `services/core/cmd/atlas_core/main.go:235-241,243-304`
6. **Expected:** Route auth policy declared once at the route group and enforced by the router (e.g. `r.Route("/admin", ...)` with a group middleware, public group separate from protected), so adding a route inherits its group's policy and the middleware contains no path-string knowledge of individual endpoints; the feed endpoint's auth result passed to the server explicitly (see sibling report `2026-09-18-feed-config-mutation-auth-flag.md`).
7. **Actual:** `CombinedAuth` is a single global middleware (main.go:241) that decides per-request from path text: `IsPublicUnauthenticatedPath` lists `/health`, `/readiness`, `/admin/auth/login` (middleware.go:35-37), the `/feed` exemption is a raw literal `r.URL.Path == "/feed"` (middleware.go:180, not trailing-slash-normalized unlike the list helper at :30-33), and three more special cases are path-text predicates (`isLogoutPath` :116-119, `isAPIKeyAdminPath` :121-124, `isResourcesPath` :126-128). Because `/feed` is exempted, `handler.Feed` re-implements auth (handler_feed.go:29-52: API key via `ValidAPIKeyOrManagedResult`, then session via `AuthenticateRequest`) and signals success by mutating `serverConfig` (`EnableAPIAuth=false`, `APIKey=""`, `SkipOriginCheck=true` at :37-39 and :49-50); `feed.Server` then runs its own partial checks (server.go:50-54 key-configured 503, :55-58 origin, :83-89 auth-frame gate keyed off `EnableAPIAuth`, :277-279 frame-first rule).
8. **Reproduction:** Source trace of the scattering: main.go:235-241 registers `CombinedAuth` globally before all routes (chi requirement noted at :235); routes are flat `r.Get/r.Post` calls at main.go:243-304 with no per-group policy. /feed flow: middleware.go:180 exempts `/feed` → handler_feed.go:25-60 re-authenticates → feed/server.go:50-58,83-89 re-checks. **Dev-mode inconsistency claim DISPROVEN:** with `ENABLE_API_AUTH=false` and no session cookie — (a) `GET /entities`: middleware.go:192 skips the API-key block (`enableAPIKey=false`, path not `/resources`), `adminAuth.AuthenticateRequest` fails (admin.go:250-254: no cookie → `ErrInvalidSession`; no dev bypass exists), middleware.go:212 → 401. The normal API is NOT open. (b) `GET /feed`: exempted at middleware.go:180 → handler_feed.go:30 block skipped (`EnableAPIAuth=false`) → session check fails (:42-43) → handler_feed.go:57-59 → 401. Both 401; no split. Corroborating tests: `handler_feed_test.go:100-124` (`TestFeedRejectsUnauthenticatedWhenAPIAuthDisabled` — 401 with auth disabled), `middleware_test.go:373-390` (`TestCombinedAuthProtectsRootPath` — 401 by default), `middleware_test.go:432-456` (session accepted in both API-auth modes). **"New route quietly exposed" claim DISPROVEN in its strong form:** chi router middleware applies to every route on the router and main.go registers exactly one chi router with no `Mount`/`Group`/`Route`/second mux (verified by grep over `services/core`); a new route not matching an exemption falls through to the API-key and session checks → 401 without credentials, so exposure requires a deliberate edit to `IsPublicUnauthenticatedPath` or registration at exactly `/feed`.
9. **Notes:** Honest risk calibration: the real hazard is not silent exposure of new routes — the middleware is deny-by-default and a new route cannot escape it — but (1) the exemption policy lives as path text in middleware.go, far from the route declarations in main.go, so adding a genuinely public route means editing a switch statement where the blast radius (all methods, all handlers at that path) is easy to misjudge, and the `/feed` literal at middleware.go:180 must be kept in sync with the `r.Get("/feed", ...)` registration at main.go:252 by hand; (2) the `/feed` exemption forces the handler-level re-auth and flag mutation, so a future streaming endpoint copied from this pattern must remember to re-implement the whole auth dance — that duplication, and the dual-meaning `EnableAPIAuth` flag, are analyzed in depth in the sibling report `2026-09-18-feed-config-mutation-auth-flag.md` (this report is the architecture-level view, not a duplicate of its flag-semantics defect). Two real but different asymmetries were found while disproving the dev claim: with a valid session, normal GETs need no `Origin` header (middleware.go:204 checks Origin only for unsafe methods) while `/feed` demands a trusted Origin even for session-authenticated non-browser clients (handler_feed.go:44); and with `ENABLE_API_AUTH=false` a valid API key is honored on `/resources` (middleware.go:192 forces the check there) but ignored everywhere else, including `/feed`. Neither exposes data. The scattered-rules structure is confirmed and worth the route-group refactor; the severity reflects that no current path is open that should be closed.
