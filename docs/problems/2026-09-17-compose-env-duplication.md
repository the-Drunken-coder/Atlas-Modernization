# Problem: Compose environment construction is duplicated and Compose `inherit` plumbing is dead

1. **Time & Date:** 2026-09-17T11:38:13-04:00
2. **Name:** Keep Compose command and log-stream environment policy in one path
3. **Issue:** The Core CLI has two independent implementations of the sanitized Compose environment, while the synchronous Compose helper still carries an `inherit` argument that no Compose caller enables. This is a maintenance defect because a future Compose environment assignment or output-policy change can update one path and silently leave normal commands and log streams with different behavior.
4. **Severity:** S5 (Note)
5. **Location:** `surfaces/core-cli/src/application.ts:5269-5286,5313-5374`; Compose callers at `:3015,5382`
6. **Expected:** A shared helper should construct the sanitized Compose environment and be used by both `#runComposeFile` and `#runComposeStream`. The Compose helper should not expose an `inherit` parameter once all Compose calls capture output; the general `RunOptions.inherit` should remain available for commands that intentionally inherit terminal output.
7. **Actual:** `#runComposeFile` scrubs and populates `env` at `:5322-5336`, and `#runComposeStream` repeats the same policy at `:5358-5370`. `#runCompose` accepts `inherit` and forwards it at `:5269-5285`, but all of its call sites pass `false` (`#composeServiceStates` at `:3015` and `#runComposeChecked` at `:5382`); all direct `#runComposeFile` calls also pass `false`. A legitimate future change made in only one duplicated block can therefore make `atlas-core logs` and lifecycle/plugin Compose commands use different environment policy.
8. **Reproduction:**
   1. Inspect the two Compose execution paths and add or change one Compose-only environment assignment in only one block, as a contributor following the existing structure might do.
   2. Run a lifecycle/plugin operation that uses `#runComposeFile`, then open `atlas-core logs`, which uses `#runComposeStream` (`:3114-3122`). The two Docker Compose processes receive different environment values even though they operate on the same deployment.
   3. Independently trace `#runCompose` callers: both pass `false`, so changing its `inherit` argument cannot affect any current Compose invocation.
9. **Notes:** The direct recovery-forward path at `:2084-2098` passes `inherit: true` to `this.#runner.run` for the npm child so its terminal output remains visible. That is valid `RunOptions` plumbing and does not disprove the narrower dead-Compose-parameter claim. No current runtime mismatch was found: both Compose blocks currently assign the same values, and the issue has no user-facing impact until one path is changed. The focused test command was attempted with Node 24 but could not start because this checkout has no installed `vitest` binary (`npm test --workspace atlas-core -- --run test/application.test.ts -t 'logs'`); static call-site inspection and `git diff --check` are the available checks.
