2. **Name:** Gateway caches in-band Overpass timeout remarks
3. **Issue:** The Building Scan connector caches an Overpass HTTP 200 response for 60 seconds even when its JSON body contains a timeout or busy `remark`, so a repeated search can replay the source failure instead of retrying Overpass.
4. **Severity:** S3 (Moderate)
5. **Location:** `plugins/building_scan/source-connector.json`, `services/core/internal/sourcegateway/gateway.go` (`Gateway.execute`, `cacheableStatus`), and `plugins/building_scan/src/operation.ts` (`parseCandidates`, `overpassRemarkCode`)
6. **Expected:** A 200 response whose body is an Overpass failure remark should not be cached. A retry of the same bounding-box request within the 60-second TTL should reach Overpass again and be able to observe a recovered response.
7. **Actual:** The connector is read-only with `cache.ttl_ms: 60000` and no retries. `Gateway.execute` stores every non-retryable status accepted by `cacheableStatus`; that predicate returns true for 200. The cache key is stable for the same encoded query, headers, and body, so a second identical request returns the cached `ConnectorResponse` without calling `connector.attempt`. The Building Scan operation then parses the cached JSON `remark` and reports `source_timeout` or `source_busy` again.
8. **Reproduction:**
   1. Configure the Source Gateway with `plugins/building_scan/source-connector.json` and arrange for Overpass (or a test transport) to return `plugins/building_scan/test/fixtures/remark-timeout.json` with HTTP 200 for a Building Scan request.
   2. Issue the same Building Scan request for the same area twice within 60 seconds, with identical POST body and headers.
   3. Observe that the first Gateway execution reports `cache_result=stored`, the second reports `cache_result=hit`, the upstream call count remains one, and both plugin invocations fail as `source_timeout` (or use a busy remark and observe `source_busy`).
9. **Notes:** The plugin test in `plugins/building_scan/test/operation.test.ts` confirms that a 200 `remark-timeout.json` body maps to `source_timeout`, but it mocks the Gateway client and does not exercise Gateway caching. The Gateway tests pass for ordinary 200 caching and for the explicit 429/5xx exclusions, leaving this in-band 200 failure case uncovered.
