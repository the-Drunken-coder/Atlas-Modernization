# Problem Report

1. **Time & Date:** 2026-08-30T15:05:30Z
2. **Name:** Generated TypeScript RFC3339 predicate rejects valid Protocol timestamps
3. **Issue:** The canonical Protocol schema's `date-time` contract and the Go validator accept RFC3339's permitted lowercase `t`/`z` forms and correctly placed leap seconds, but the generated TypeScript predicate rejects them. A valid Core request or resource carrying such a timestamp can therefore fail SDK validation.
4. **Severity:** S4 (Minor)
5. **Location:** `packages/protocol/schema/jsonschema/atlas.schema.json`, `packages/protocol/tools/internal/artifacts/typescript_runtime_helpers.go`, `packages/protocol/generated/typescript/index.ts`, and Core entity request/serialization paths in `services/core/internal/api/handlers/handler_response.go`, `services/core/internal/api/handlers/handler_entity.go`, and `services/core/internal/serializers/serializers.go`
6. **Expected:** The generated TypeScript runtime predicates accept every timestamp accepted by the canonical `RFC3339Timestamp` schema and Go validator, including lowercase `t`/`z` and a leap second represented at an equivalent UTC instant. The SDK should accept a valid Protocol/Core entity request or response containing those timestamps.
7. **Actual:** The generated helper uses an uppercase-only `T`/`Z` regular expression and rejects every second greater than 59 (`typescript_runtime_helpers.go:75-103`). The Go validator compiled from the canonical schema accepts `2026-01-02t03:04:05Z`, `2026-01-02T03:04:05z`, `2026-01-02T23:59:60Z`, and `2026-01-02T00:59:60+01:00`; the generated TypeScript `isRFC3339Timestamp` returns `false` for each of them. The same mismatch appears in `isEntityCreateRequest` when `components.heartbeat.last_seen` carries one of these values. Core validates the raw request before typed decoding (`handler_response.go:220-260`), keeps component timestamps in a generic map (`handler_requests.go:10-18`), validates them through the Go Protocol path, and serializes stored components without rewriting them (`serializers.go:27-50`). Core-generated metadata timestamps normally use uppercase `time.Format` output, so this primarily affects externally supplied component timestamps and uncommon leap-second inputs.
8. **Reproduction:**
   1. Against the checked-out Protocol module, evaluate `validator.ValidateDefinition("RFC3339Timestamp", value)` for `2026-01-02t03:04:05Z`, `2026-01-02T03:04:05z`, `2026-01-02T23:59:60Z`, and `2026-01-02T00:59:60+01:00`; the isolated Go probe returned `[]` for each. It rejected invalid controls `2026-01-02T23:59:60+01:00`, `2026-01-02T03:04:60Z`, and the non-leap date `2026-02-29T03:04:05Z`.
   2. From the repository root after the locked workspace dependencies are installed (`npm ci`), run the generated TypeScript predicate directly from the checked-in source with `tsx`:
      ```sh
      node --import tsx --input-type=module -e 'import {isRFC3339Timestamp,isEntityCreateRequest} from "./packages/protocol/generated/typescript/index.ts"; const values=["2026-01-02t03:04:05Z","2026-01-02T03:04:05z","2026-01-02T23:59:60Z","2026-01-02T00:59:60+01:00"]; for (const value of values) console.log(value,isRFC3339Timestamp(value),isEntityCreateRequest({entity_id:"asset-1",entity_type:"asset",components:{heartbeat:{last_seen:value}}}));'
      ```
      Observe `false false` for every value. The corresponding uppercase ordinary timestamp and numeric-offset control return `true`.
   3. A Core `POST /entities` request with `components.heartbeat.last_seen` set to one of the Go-accepted values passes the raw Protocol validator and reaches the generic component/action path; the SDK's response/resource predicate then rejects the returned component timestamp.
9. **Notes:** This is a cross-language contract defect, not a normal Core-emission failure: Core formats generated metadata with uppercase `RFC3339`/`APIMetadataTimeLayout`, and standard timestamps therefore pass both implementations. The smallest fix is to align the generated TypeScript helper with the canonical date-time semantics (including case-insensitive `t`/`z` and leap-second rules), then add shared Go/TypeScript conformance cases for valid lowercase forms, UTC leap seconds, equivalent offset leap seconds, invalid non-equivalent offsets, ordinary `60` seconds, and invalid dates. Update the source generator and regenerate artifacts; do not hand-edit `generated/typescript/index.ts`.
