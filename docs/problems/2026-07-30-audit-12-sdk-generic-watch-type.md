# Generic SDK watch permits filter and callback type mismatches

1. **Time & Date:** 2026-07-30T08:33:00Z
2. **Original Audit Finding:** 12
3. **Validation Status:** Confirmed against `main` at `2426bb6`.
4. **Name:** Generic SDK watch permits filter and callback type mismatches
5. **Affected Surface & Severity:** Public `AtlasClient.watch` TypeScript API and generic `SyncEngine.watch` storage boundary; S3 (Moderate). TypeScript consumers can compile code whose callback is promised one resource type but receives another at runtime.
6. **Current vs. Expected:** Callers may explicitly instantiate `client.watch<TaskResource>(...)` while passing an entity filter. TypeScript accepts the call, and the engine casts any delivered `ResourceValue` to the independently chosen `T`. The callback type should be derived from the subscription discriminator: entity filters receive entities, task filters and `tasks_for_entity` receive tasks, object filters receive objects, and `all` receives the resource union.
7. **Concrete Source Evidence:** `atlas_sdk/src/types.ts:30-34` defines the discriminated `AtlasSubscription` union and `:203-210` already defines `ResourceByType`/`ResourceOf`. `atlas_sdk/src/client.ts:263-268` declares `T` independently of `filter`. `atlas_sdk/src/sync-engine.ts:150-159` repeats that independent generic and performs `resource as T | undefined`. Resource-specific convenience watches at `atlas_sdk/src/client.ts:101-102`, `:175-176`, and `:195-196` are correctly typed and are not affected.
8. **Reproduction / Static Proof:** The following temporary consumer compiled with TypeScript 7.0.2 under `--strict` and exit code 0: `client.watch<TaskResource>({filter:"id", resource_type:"entity", id:"e"}, task => { task?.task_id; });`. The compile command was `tsc --noEmit --strict --module nodenext --moduleResolution nodenext --target es2023 --skipLibCheck --ignoreConfig --types node /tmp/atlas-watch-unsound.ts`. At runtime the subscription router selects entity events from the filter; the cast at `sync-engine.ts:158` does not transform the entity into a task.
9. **Root Cause:** The API exposes a caller-selected resource generic instead of relating the generic to the filter's `resource_type`, then suppresses the resulting internal mismatch with a broad cast.
10. **Simplest Correct Proposed Solution:** Make `watch` generic over the subscription shape and derive its callback resource through a small conditional/keyed type based on that filter. Do not expose an independent resource generic. Keep the existing resource-specific convenience methods unchanged.
11. **Acceptance Criteria / Regression-Test Plan:** Add type tests that accept entity/entity, task/task, object/object, `tasks_for_entity`/task, and `all`/union callbacks; reject an entity filter paired with a task callback; and prevent an explicit generic from overriding the filter. Retain runtime watcher routing tests and remove the `resource as T` assertion from the storage boundary.
12. **Scope / Non-Goals:** Do not redesign subscriptions, add runtime type tags beyond those already present, or split the watch implementation into per-resource engines.
13. **Overlaps:** Finding 31 is in the same sync-engine file but concerns error-state coupling. Finding 4 concerns event ordering and cache deletion, not TypeScript API soundness.
