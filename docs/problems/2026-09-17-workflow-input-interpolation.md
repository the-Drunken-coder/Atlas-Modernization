# Problem: Plugin catalog release workflows retain temporary Git credentials

1. **Time & Date:** 2026-09-17T11:38:07-04:00 America/New_York
2. **Name:** Keep release workflow inputs and Git credentials out of avoidable shell/config persistence
3. **Issue:** The Plugin release workflow expands manual inputs directly into three downstream shell scripts, and the Plugin release, renewal, and revocation workflows write `GITHUB_TOKEN` into `catalog-ledger/.git/config` as an HTTPS remote URL without removing it. The input expansion is not currently an exploitable injection because every path that reaches those steps is gated by strict validation, but the remote URL is a real same-job credential-retention seam and should be treated as defense-in-depth maintenance.
4. **Severity:** S5 (Note)
5. **Location:** `.github/workflows/release-atlas-plugin.yml:122,427-446`; `.github/workflows/publish-plugin-catalog.yml:47-64`; `.github/workflows/revoke-plugin-catalog.yml:61-82`; input validation in `scripts/plugin-release.mjs:12-13,31-39,117-125,680-693`
6. **Expected:** Keep workflow inputs in environment variables or other typed action inputs all the way through shell steps. Authenticate the catalog push with an ephemeral header/helper, or clear the credential-bearing remote URL immediately after the push, so the token is not readable from local Git configuration for the rest of the job.
7. **Actual:** `release-atlas-plugin.yml:122` passes `${{ inputs.version }}` directly to a shell `run`, and lines `438` and `444` directly expand both inputs into a path and commit message. The validation job runs first and strict `plugin_id`/stable-SemVer checks reject shell metacharacters, so malformed values fail before the `build` and `publish` jobs (`needs: validate` at `:81` and `:242`). The three catalog workflows then execute `git remote set-url` with `x-access-token:${GH_TOKEN}` (`release-atlas-plugin.yml:436`, `publish-plugin-catalog.yml:57`, and `revoke-plugin-catalog.yml:74`) and contain no `git config --unset`/remote restoration. A subsequent `git config --get remote.origin.url` in the same job can therefore read the token-bearing URL.
8. **Reproduction:**
   1. Inspect `scripts/plugin-release.mjs:12-13,691-693` and `readPlugin` at `:117-125`; values such as `building_scan$(id)` or `1.2.3; touch /tmp/pwned` do not pass the identifier or SemVer patterns. The `validate` job is a prerequisite for every step containing a direct input expression.
   2. Inspect the catalog mutation steps at the locations above. `actions/checkout` deliberately uses `persist-credentials: false`, then the workflow writes a synthetic equivalent of `https://x-access-token:<token>@...` with `git remote set-url`.
   3. Run `git config --get remote.origin.url` after that command; Git returns the credential-bearing URL from `.git/config` until it is explicitly changed or the workspace is destroyed. No cleanup command exists in any of the three workflows.
   4. The current exposure is bounded: these jobs use `runs-on: ubuntu-latest`, the ledger directory is not copied into the Pages artifact (only `catalog.json` and its signature are copied), and no later step prints or uploads `.git/config`. Each job also starts from a fresh checkout, so this is not cross-job credential persistence.
9. **Notes:** This is confirmed as a low-impact credential-hygiene/maintenance issue, not a current command-injection or demonstrated credential-leak vulnerability. The direct interpolation portion of the source report is mitigated at this SHA by validation ordering and should not be escalated without a future bypass or relaxed validator. The Core release workflow uses environment variables for its shell `VERSION` uses; its `run-name`, action inputs, and concurrency expressions are not shell contexts. A Ruby YAML parse of all `.github/workflows/*.yml` passed, the static malicious-input pattern checks passed, and `git diff --check` passed. The focused Node release tests could not start because the available Node binary is missing Homebrew `libllhttp.9.3.dylib`; no product or test files were changed.
