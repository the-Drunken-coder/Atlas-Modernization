1. **Time & Date:** 2026-09-18T15:00:56Z
2. **Name:** Protocol revision hashes raw schema bytes, so cosmetic schema edits force coordinated Plugin republishes
3. **Issue:** The "protocol revision" that Core, the SDK, and the plugin manager compare for exact equality is a SHA-256 of the raw bytes of `packages/protocol/schema/jsonschema/atlas.schema.json`. Nothing canonicalizes the schema first, so fixing a typo in a `description`, changing whitespace, or re-ordering keys silently produces a brand-new revision. Every SDK-backed Plugin release declares the old hash in its immutable release document and is then rejected as incompatible, forcing a plugin republish plus a coordinated Core transition for a semantically meaningless edit.
4. **Severity:** S4 (Minor) — latent compatibility hazard; nothing has shipped, the coupling is documented, and the disable/update/re-enable workaround exists, but every cosmetic schema touch triggers the painful path.
5. **Location:** `packages/protocol/tools/internal/artifacts/revision.go:12-25`; `packages/protocol/schema/jsonschema/atlas.schema.json`; `packages/sdk/src/feed-connection.ts:332-336`; `packages/sdk/src/sync-engine.ts:162-172`; `surfaces/core-cli/src/plugin-distribution.ts:156,181,195,358-379`; `surfaces/core-cli/src/package-metadata.ts:8`; `surfaces/core-cli/src/managed-core.ts:287,946`; `services/core/internal/api/handlers/handler_protocol.go:10-12`; `services/core/internal/feed/server.go:193`
6. **Expected:** The protocol revision should change only when the schema's contract changes (types, required fields, constraints, wire shapes). Documentation-string or formatting edits should not invalidate every SDK-backed Plugin release, given the decision that Plugins release independently of Core (`docs/atlas-plugins/README.md:31,45-50`).
7. **Actual:** `protocolRevision` reads the schema file with `os.ReadFile` and hashes path + NUL + bytes + NUL with no normalization. A one-word fix inside an existing `description` string changes the revision (verified: `sha256:4cd40a5b...14b44` → `sha256:952e82c5...116cb3`). Core then reports the new hash (`GET /protocol/revision`, feed `hello`), the SDK throws `ProtocolMismatchError` on any mismatch, and `assertPluginCompatible` rejects every Plugin release whose `atlas_protocol_revision` (a strict required field of the signed `.atlas-plugin` document) equals the old hash — blocking install/enable/update and the Core-update preflight until each Plugin is republished against the new revision.
8. **Reproduction:**
   1. Copy `packages/protocol/schema/jsonschema/atlas.schema.json` to a temp tree (Go toolchain unavailable in this environment, so the 5-line hash from `revision.go:12-25` was replicated exactly in Node; the replica reproduces the committed `packages/protocol/generated/go/atlasprotocol/revision.go` constant `sha256:4cd40a5b37578ecfceb1d094f611c2ff9f369dfa8659238c56489f1c94814b44` byte-for-byte, proving no normalization occurs).
   2. Edit one existing description string only: `"Sources must convert other vertical references..."` → `"...the other vertical references..."` (line 400 of the schema).
   3. Recompute the hash: it changes to `sha256:952e82c5397ea4fe37fb8ab6ca7996901c048037448bb49b040def5865116cb3`. `go run ./tools/generate` from `packages/protocol/` would stamp this new hash into `generated/go/atlasprotocol/revision.go`, `generated/typescript/index.ts` (`ATLAS_PROTOCOL_REVISION`), and `generated/revision.txt`.
   4. Trace the consequences: Core serves the new hash; SDK `assertRevision` (`feed-connection.ts:332-336`, called from `sync-engine.ts:171` and feed hello at `:143,257`) throws `ProtocolMismatchError`; plugin manager `assertPluginCompatible` (`plugin-distribution.ts:370-372`) throws "Plugin requires a different Atlas Protocol revision" for every SDK-backed release, and the Core-update preflight (`managed-core.ts:287,946`) blocks the update per `docs/atlas-plugins/MANAGEMENT.md:426-434`.
9. **Notes:** Searched for disconfirming evidence on all three fronts and found none: (a) no canonicalization — the generator parses the schema for type generation (`schema_generation.go:117-130`) but the hash reads raw bytes; the `TestProtocolRevisionIgnoresUnloadedJSONFiles` test only proves *unrelated* files are excluded. (b) The revision is baked into immutable release documents — `atlas_protocol_revision` is a required strict-JSON field of the `.atlas-plugin` document (`plugin-distribution.ts:156,181,195`), so old releases cannot be re-pointed, only republished at a new semver. (c) No negotiation — the comparison is exact string equality with no major-version fallback; `ProtocolMismatchError` is unconditional. The coupling itself is documented as accepted design (`docs/atlas-plugins/README.md:45-50`, `docs/atlas-protocol/README.md:46` calls the stamp "a drift/mismatch token, not compatibility versioning"), but the raw-bytes mechanism makes "a Protocol revision change" fire on semantically irrelevant edits, in tension with the independent-release decision. Non-SDK Plugins (revision `null`) are unaffected. Candidate fixes if pursued: hash a canonicalized form of the schema (parse → re-marshal sorted/stable), or hash only structural content with descriptions/whitespace stripped. Severity argued as S4 rather than S3 because the break is future-conditional and the disable → update Core → republish → enable dance is a documented, working process.
