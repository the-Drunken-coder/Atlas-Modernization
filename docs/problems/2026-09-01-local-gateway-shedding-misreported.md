1. **Time & Date:** 2026-09-01T22:42:23-04:00
2. **Name:** Local Source Gateway admission timeout is reported as upstream timeout
3. **Issue:** A request that expires while waiting for a connector concurrency slot or rate-limit admission is classified as `upstream_timeout`, even though no upstream attempt was made.
4. **Severity:** S3 (Moderate)
5. **Location:** `services/core/internal/sourcegateway/gateway.go:300-319,572-574`, `plugins/building_scan/source-connector.json:18-26`, and `plugins/building_scan/src/operation.ts:80-110`
6. **Expected:** `upstream_timeout` and HTTP `504` should mean that a bounded outbound attempt contacted the upstream and timed out. A request shed locally while waiting for connector admission should have a distinct busy/admission outcome, or the upstream timeout budget should begin only after admission.
7. **Actual:** `execute` starts `requestContext` with the connector's `timeout_ms` before selecting `connector.semaphore` and before `waitForRate`. If the sole slot is occupied until that deadline, the waiter exits through `timeoutOrCancellation`, which always returns `FailureUpstreamTimeout`; the Gateway emits `504` with `{"code":"upstream_timeout"}`. Building Scan's `requestSource` maps that code directly to the user-facing `source_timeout`, despite `connector.attempt` never running for the waiter. The shipped connector sets `timeout_ms` to 15000, `max_concurrency` to 1, and a rate limit of 0.2 requests per second.
8. **Reproduction:**
   1. Construct a local Source Gateway connector with `timeout_ms: 50`, `max_concurrency: 1`, and an `http.RoundTripper` whose first request blocks until its context is canceled; use the connector's normal `execute` path and count transport calls.
   2. Start two identical `execute` calls concurrently, with the first acquiring the semaphore before the second starts.
   3. Wait for the 50 ms deadline. The first call makes one `connector.attempt`; the second returns a `gatewayError` with code `upstream_timeout` while the transport call count remains one, proving it never contacted the upstream.
   4. Serve the second error through `Gateway.Handler()` and observe HTTP `504` with `{"code":"upstream_timeout"}`. Pass the same Gateway failure through `plugins/building_scan/src/operation.ts`'s `requestSource` mapping and observe Plugin code `source_timeout`.
9. **Notes:** The Source Gateway contract defines `upstream_timeout` as "the bounded upstream attempt timed out" (`docs/atlas-plugins/README.md:202-211`). The complete Source Gateway package test run passed at this checkout, but does not cover a timeout while waiting for semaphore admission; the Building Scan test run also passed (23/23), with its existing mapping test asserting `upstream_timeout` to `source_timeout` but not local admission-timeout behavior.
