# Problem: Storage recovery coverage contracts are maintained across Python and Go

1. **Time & Date:** 2026-09-17T11:38:07-04:00 America/New_York
2. **Name:** Keep curated storage test selection and coverage baselines synchronized
3. **Issue:** The storage-recovery runner's exact Go test selection is encoded as a 31-name Python allow-list, and its statement-ratio floors are also encoded as Python constants. A harmless rename of a selected Go test therefore requires a synchronized Python edit, creating a small cross-language maintenance seam. The current behavior is intentional and does not constitute a product or CI defect.
4. **Severity:** S5 (Note)
5. **Location:** `services/core/scripts/verify_storage_recovery_tests.py:11-49,72-81`; selector use in `services/core/scripts/run_storage_recovery_tests.sh:359-381`; floors in `services/core/scripts/check_storage_recovery_coverage.py:25-34,93-105` and `services/core/scripts/check_coverage.py:8-14,59-68`
6. **Expected:** The repository should either centralize the curated test names and coverage policy or document this deliberate test-contract coupling so contributors know that renaming or removing a selected Go test requires updating the Python selector and its verification tests.
7. **Actual:** `verify_storage_recovery_tests.py` stores 31 exact test names, generates the `-run` expression from them, and reports a missing selected test as an error. The shell runner passes that expression to `go test` and then verifies every expected pass event. The two coverage checkers keep rational statement floors in Python and compare ratios exactly by cross-multiplication; these are percentage ratchets rather than fixed statement-count requirements.
8. **Reproduction:**
   1. Run `go test ./internal/actions -list '^Test'`; the current package lists 169 tests. Generate the runner pattern with `python3 scripts/verify_storage_recovery_tests.py pattern`; it selects exactly 31 names, all of which currently exist.
   2. Rename one selected Go test without changing `verify_storage_recovery_tests.py`. The generated pattern no longer selects the renamed test, and the event verifier reports `selected storage recovery test did not pass: <old name>`; updating the Python allow-list is required for the harmless rename to pass.
   3. Inspect the ratchet arithmetic. `check_storage_recovery_coverage.py:103-104` compares `covered * floor.total` with `floor.covered * total`, so adding statements does not require changing the hard-coded denominator unless the policy ratio itself changes. The current source-only coverprofile has 3,157 total statements and 2,745 actions statements versus the historical 3,142 and 2,730 baselines, demonstrating that the denominators are ratio representation rather than exact-total assertions.
9. **Notes:** This is a maintenance note, not a confirmed substantive defect. The exact selection is a deliberate safety contract: `docs/STORAGE_RECOVERY_TESTING.md:17` says a missing selected test fails the run, and the document records successful runs of all 31 selected tests at `:75-77,83`. The analogous live-transaction runner also uses a curated Python allow-list.
