# Problem Report

1. **Time & Date:** 2026-08-30T14:54:36Z
2. **Name:** Entity PATCH and check-in round existing arbitrary JSON integers
3. **Issue:** Entity JSON blob patching decodes the existing blob with Go's default `encoding/json` behavior, which converts JSON numbers to `float64`. Any entity PATCH or check-in that rewrites the blob can therefore change an existing integer that is outside the exact IEEE-754 range.
4. **Severity:** S3 (Moderate)
5. **Location:** `services/core/internal/actions/entity_actions.go`, `services/core/internal/actions/json_blob_contracts.go`, `services/core/internal/actions/entity_checkin_actions.go`
6. **Expected:** Updating an unrelated entity field, or recording a check-in, preserves every existing JSON value semantically, including an accepted arbitrary integer such as `9007199254740993`. JSON member ordering or insignificant lexical formatting need not remain byte-for-byte identical.
7. **Actual:** `EntityActions.Update` calls `patchValidatedJSONBlob` with `jsonBlobDecodeDefault`; `decodeJSONBlobForPatch` then uses `json.Unmarshal`, converting `9007199254740993` to `float64(9007199254740992)`. `json.Marshal` stores the rounded value. `EntityCheckinActions.CheckIn` always calls this update path after adding heartbeat/telemetry data, so it also rewrites unrelated existing values.
8. **Reproduction:**
   1. Create an entity with the complete valid request `{"entity_id":"asset-1","entity_type":"asset","extra":{"precise":9007199254740993}}`. The request decoder and create path preserve this JSON number, and the `EntityBlob`/`JSONValue` contract accepts it.
   2. PATCH the entity with an unrelated extra field, for example `{"extra":{"operator_note":"updated"}}`. In `entity_actions.go`, the existing JSON is passed to `patchValidatedJSONBlob` using `jsonBlobDecodeDefault`; in `json_blob_contracts.go`, that mode calls `json.Unmarshal` into `map[string]interface{}`.
   3. GET the entity and observe `extra.precise` is `9007199254740992`, not `9007199254740993`. The same result occurs after `POST /entities/{entity_id}/checkin` (even with an otherwise empty body), because `entity_checkin_actions.go:35` delegates to `Update`, which adds a heartbeat and writes the merged blob.
   4. Focused checks: `go test ./internal/actions -run 'Test(DecodeObjectJSONForPatchStillPreservesNumbers|MergeEntityComponents)' -count=1 -v` and `go test ./internal/api/handlers -run 'TestTaskRequestPreservesExactJSONNumbers' -count=1 -v` pass, demonstrating the repository's `UseNumber` path preserves exact values while the entity path explicitly selects the default decoder. The entity path's conversion follows directly from Go's documented `encoding/json` default number handling; no live database or destructive operation was required.
9. **Notes:** The object patch path already uses `jsonBlobDecodeUseNumber` in `object_json_contracts.go`, and task request decoding has a focused exact-number regression test. The smallest fix is to use `jsonBlobDecodeUseNumber` for entity JSON patching and add an entity PATCH/check-in regression test that reads back a large integer unchanged. Verify nested numbers in both `components` and `extra`, not only a top-level field.
