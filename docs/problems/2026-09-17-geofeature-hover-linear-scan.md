# Problem: Geo Feature hover classification scans the full source

1. **Time & Date:** 2026-09-17T15:20:14Z
2. **Name:** Geo Feature hover classification performs a source-wide linear scan
3. **Issue:** Each processed pointer move that has a hover target classifies that target by scanning the entire `sources.geofeatures.features` array, even though canvas hover candidates come from layers that are exclusively Geo Feature layers. The avoidable scan adds O(G) main-thread work per animation frame, where G is the loaded Geo Feature count.
4. **Severity:** S4 (Minor)
5. **Location:** `surfaces/command-interface/src/ui/map/interaction/use-map-reticle-pointer.ts:177-207`; `surfaces/command-interface/src/ui/map/interaction/map-targets.ts:19-22,80-94`; `surfaces/command-interface/src/ui/map/rendering/map-layers.ts:19,67-94`
6. **Expected:** Hover target classification should retain the feature kind from the hit-test path, or otherwise resolve it in O(1), while preserving marker-first selection and the non-expanding cursor behavior for Geo Features.
7. **Actual:** `flushPointer()` calls `hoverSelectionTarget()` and then, whenever it returns a target, runs `sources.geofeatures.features.some(...)` to determine whether the target is a Geo Feature (`use-map-reticle-pointer.ts:186-203`). `hoverSelectionTargets()` queries only `INTERACTIVE_LAYERS` (`map-targets.ts:80-94`), and those layers are `geofeatures-point`, `geofeatures-line`, and `geofeatures-fill` (`map-layers.ts:19,67-94`). The returned `HoverTarget` retains only `entityId` and its box (`map-targets.ts:21-22`), forcing the caller to recover the discarded type by scanning the complete source. The pointer hook coalesces native events to one `requestAnimationFrame` callback (`use-map-reticle-pointer.ts:209-224`), so this is once per processed frame rather than once per raw event. An asset/track marker hit scans all Geo Features before returning false; a Geo Feature hit near the end of source order scans nearly all entries.
8. **Reproduction:**
   1. Load the command map with a large Geo Feature collection and at least one selectable marker or rendered Geo Feature. `MapConsole` builds the map source from all entities in the hydrated snapshot (`surfaces/command-interface/src/features/MapConsole.tsx:351-367`); the SDK's `sync: "all"` hydration paginates and then installs all entity pages (`surfaces/command-interface/src/atlas/data-source.ts:53-67`; `packages/sdk/src/sync-engine.ts:694-720`), so the 1,000-row API page size does not bound the in-memory source.
   2. Move the pointer over the marker or within the hover magnet radius of a Geo Feature. `onPointerMove` schedules `flushPointer()` for the next animation frame (`use-map-reticle-pointer.ts:209-224`).
   3. In that callback, observe `hoverSelectionTarget()` querying the Geo Feature-only interactive layers and then the following `.some(...)` traversing `sources.geofeatures.features` to classify the selected ID (`use-map-reticle-pointer.ts:186-203`). Repeat pointer movement while the target remains under the cursor to repeat the O(G) traversal once per frame.
   4. A focused test can make the source contain N Geo Features, return an unrelated marker as the hover target, and instrument the source predicate or compare callback work as N grows. The current tests exercise Geo Feature selection with one fixture but do not assert classification complexity (`surfaces/command-interface/src/ui/map/view/MapView.wheel.test.tsx:226-277`).
9. **Notes:** This report is limited to the confirmed repeated linear lookup. No claim is made that ordinary datasets visibly drop frames, nor that the MapLibre hit test itself is O(G); MapLibre performs the spatial query. The source has no explicit Geo Feature count cap, and the full snapshot can contain multiple pages, so the cost is not statically bounded to one API page. The existing behavior is functionally correct.
