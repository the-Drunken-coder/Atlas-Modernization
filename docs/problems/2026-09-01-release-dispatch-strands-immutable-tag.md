2. **Name:** Release coordinator cannot rerun after authorization upload failure
3. **Issue:** The release coordinator pushes an immutable release tag and dispatches its tag-publication run before uploading the authorization artifact that the child run requires. A failure in that upload leaves the automatic publication path failed and requires manual tag recovery.
4. **Severity:** S4 (Minor)
5. **Location:** `.github/workflows/release-atlas-core.yml:1507-1613` (`commit-release`), especially the tag push at `1522`, dispatch at `1525-1558`, authorization generation at `1567-1605`, and upload at `1607-1613`; the child wait is at `428-459`.
6. **Expected:** Once the release commit and immutable tag have been pushed, a transient authorization-artifact upload failure should be retryable from the coordinator without creating another release commit or requiring a second manual approval. The child publication run should receive the authorization and finish automatically.
7. **Actual:** The coordinator pushes `HEAD:main` and `atlas-core-v$VERSION` atomically, dispatches the child run, and only then uploads the authorization artifact. If that upload fails, the child can wait 120 seconds in `authorize-tag-publication` and fail because the named artifact does not exist. Rerunning the failed `commit-release` job re-enters its staging guard, where `origin/main` is now the release commit rather than the original `SOURCE_SHA`, so it exits with `main moved after release approval`; it cannot reach the upload step. The immutable tag remains, but automatic publication is interrupted and recovery needs a separate manual dispatch from the tag and another `release` approval.
8. **Reproduction:**
   1. Dispatch **Release Atlas Core** from `main`, approve it, and let `publish` succeed. In the source trace, `commit-release` commits and atomically pushes `HEAD:main` plus `refs/tags/atlas-core-v$VERSION` at lines 1515-1523.
   2. Let the `Dispatch immutable tag publication` step at lines 1525-1558 create the child run, then make the following `Upload approved publication` action at lines 1607-1613 fail before storing its artifact.
   3. Observe that the child's `Wait for coordinator authorization` loop at lines 449-459 cannot find `atlas-core-publication-authorization-$VERSION-$GITHUB_RUN_ID-$GITHUB_RUN_ATTEMPT` and exits after 60 two-second attempts.
   4. Re-run the failed coordinator job. Its staging path fetches `origin/main` at line 1417 and compares it with the original `SOURCE_SHA` at lines 1418-1420; the atomic push has moved `main` to the release commit, so the rerun exits before `commit-release` can dispatch/upload again. The documented recovery at `docs/atlas-core/RELEASING.md:180-189` requires manually dispatching from the immutable tag with empty coordinator fields and approving `release`.
