1. **Time & Date:** 2026-09-01T22:44:14-04:00
2. **Name:** Plugin disable deletes active assets before durable membership update
3. **Issue:** A hard interruption during Plugin disable can leave `state.json` claiming that a Plugin is enabled after its Compose overlay and active files have been deleted.
4. **Severity:** S4 (Minor)
5. **Location:** Atlas Core CLI, `surfaces/core-cli/src/application.ts:1205-1216`, with recovery validation in `surfaces/core-cli/src/application.ts:1681-1694` and `1778-1795`.
6. **Expected:** An interrupted disable leaves deployment state, active Plugin files, and containers mutually recoverable, or automatically completes or rolls back the operation on the next CLI invocation without destructive reset or manual private-state surgery.
7. **Actual:** Disable copies a rollback backup, removes the Plugin container, recursively deletes the active Plugin directory, and only then replaces `state.json` with the filtered `enabledPlugins` list. A `SIGKILL`, power loss, or equivalent hard stop after `#removePluginAssets` and before `#writeDeploymentState` therefore leaves the old Plugin ID in `state.json` while its `compose.yml`, endpoint, connector, and deployment metadata are absent. The local mutation lock and Docker mutation-lock network also remain because process cleanup is bypassed. After stale locks are cleared, `start` and `restart` fail `#assertEnabledPluginDeployment` on the missing private files; `plugins disable` and status paths still build Compose arguments from the old enabled ID and cannot complete against the missing overlay. No startup recovery consumes the stranded hidden backup.
8. **Reproduction:**
   1. Initialize Atlas Core and enable a packaged query-only Plugin on a running deployment; verify its ID is in `state.json` and its active directory exists.
   2. Run `atlas-core plugins disable <plugin_id>` and stop the process with `SIGKILL` after the `docker compose rm -s -f <plugin_service>` command succeeds and `#removePluginAssets` returns, but before `#writeDeploymentState` executes. A debugger breakpoint between source lines 1211 and 1212 provides a deterministic pause for this boundary.
   3. Verify that `state.json` still lists the Plugin, `~/.atlas/core/plugins/<plugin_id>/` is absent, a hidden `.backup.*` directory remains, and the local and Docker mutation locks remain.
   4. Retry `atlas-core start` or `atlas-core restart` (after clearing the stale locks only to continue the observation). Both reject the enabled Plugin's missing private files. Retrying `atlas-core plugins disable <plugin_id>` cannot reach a successful disable because its old Compose overlay is missing.
9. **Notes:** `#pluginEnable` writes the candidate enabled-plugin state before runtime mutation at lines 1089-1100, so ordinary in-process rollback can restore it; disable uses the opposite ordering at lines 1209-1213. `writePrivateFile` atomically replaces one state file, but that does not make the preceding directory deletion and state replacement one transaction. The focused ordinary disable test passes (`npm test --workspace atlas-core -- test/application.test.ts -t 'disables with the old composition'`, 1 passed, 97 skipped), but it does not cover hard process termination between asset deletion and state write. Docker Compose independently rejects the generated missing overlay before contacting the daemon (`open /private/tmp/atlas-plugin-compose-missing.yml: no such file or directory`).
