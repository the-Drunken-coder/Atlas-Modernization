1. **Time & Date:** 2026-09-16T04:34:07Z
2. **Name:** Cancelled observations can append assertions after the browser terminal event
3. **Issue:** A stop request can mark an observations run cancelled while its verifier client is already constructed. Delayed verifier reads then append assertions after the terminal event. The browser closes its event source on that terminal event and does not continue periodic refreshes for the cancelled run, so it can omit the later assertion evidence until a manual refresh or cleanup.
4. **Severity:** S3 (Moderate)
5. **Location:** `simulations/src/server/run-store.ts`, `simulations/src/server/run-store-execution.ts`, and `simulations/src/client/use-run-session.ts`
6. **Expected:** A cancelled run must not append assertion evidence after its terminal `cancelled` status event.
7. **Actual:** The current hosted reproduction reaches `Stop requested` at sequence 7 and `cancelled` at sequence 8. The browser terminal stream closes there and its stop response contains no assertions, but the later summary contains three failed verifier assertions (`Observer assets persisted`, `Tracks persisted`, and `Object references persisted`) at `2026-09-16T04:34:06.065Z`. The source race is that `RunStore.stop` aborts and finishes the run before the in-flight verifier reads return, while `executeRun` suppresses assertions only after `run.settled` becomes true; the delayed scenario therefore calls `ctx.assert` after the cancelled terminal event but before execution settlement.
8. **Reproduction:** Run `npm run build:sdk && node --import ./simulations/node_modules/tsx/dist/loader.mjs tests/acceptance/simulations/observations-late-assertions.mjs`. It intentionally fails until the product prevents or reconciles the late assertions.
9. **Notes:** The committed acceptance case uses only `AtlasTargetConfig.clientFactory` to pause the real SDK verifier's first read until its own stop signal aborts; it does not modify product source. The browser-equivalent SSE artifact ends at sequence 8 because the client closes on the terminal status; the later summary is retained separately, proving the stream/summary divergence. The existing unit test that invokes a callback after cleanup does not cover this window because the delayed verifier returns before `run.settled` is set.
