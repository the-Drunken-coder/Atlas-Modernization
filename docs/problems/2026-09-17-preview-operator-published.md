# Problem: Preview operator is included in the published Core package

1. **Time & Date:** 2026-09-17T15:20:00-04:00
2. **Name:** Development-only TUI preview operator is compiled and published with `atlas-core`
3. **Issue:** The fixture-only preview operator is under the production `src/` tree, so the package build emits it even though it is not part of the installed CLI. The package then includes the entire `dist/` directory. This adds roughly 28 KiB of preview implementation to every published package and exposes a development-only fake as package runtime code.
4. **Severity:** S4 (Minor)
5. **Location:** `surfaces/core-cli/src/tui-preview-operator.ts:1-705`; `surfaces/core-cli/tsconfig.build.json:3-11`; `surfaces/core-cli/package.json:27-43`; `surfaces/core-cli/scripts/tui-preview.mjs:1-16`
6. **Expected:** The published npm artifact should contain the production `atlas-core` runtime only. The in-memory preview operator should remain a checkout/build-time fixture, or be emitted to a development-only location that is excluded from the package.
7. **Actual:** The build includes every `src/**/*.ts` and `src/**/*.tsx` file and emits to `dist/` (`tsconfig.build.json:3-11`). `tui-preview-operator.ts` is therefore emitted as `dist/tui-preview-operator.js`; a TypeScript emit probe produced that file at 28,833 bytes. `package.json` publishes the whole `dist/` directory (`package.json:27-31`), and `prepack` rebuilds it before packing (`package.json:39-43`). The only production CLI entrypoint imports `runCLI` from `application.ts` (`src/cli.ts:1-5`), while the preview operator is referenced only by the repository preview script and preview tests (`scripts/tui-preview.mjs:1-16`, `test/tui-preview.test.ts:1-8`). The preview script itself is not listed for publication, so the package ships the fake implementation without shipping the documented checkout-only harness that needs it.
8. **Reproduction:**
   1. Check out `43b5928ceba19bc95d00d578cc6ed9c03319167e` and inspect `surfaces/core-cli/tsconfig.build.json`; its include pattern covers `src/tui-preview-operator.ts`.
   2. Run `tsc --showConfig -p surfaces/core-cli/tsconfig.build.json`; the resolved `files` list includes `./src/tui-preview-operator.ts` and `outDir` is `./dist`.
   3. With TypeScript 7, run `tsc -p surfaces/core-cli/tsconfig.build.json --outDir /private/tmp/atlas-preview-operator-dist --sourceMap false --noEmitOnError false`; the emitted `/private/tmp/atlas-preview-operator-dist/tui-preview-operator.js` is 28,833 bytes. The local checkout lacks `@types/node`, so this probe reports TS2688 but still demonstrates the compiler's file emission; CI installs the package dependencies before `npm pack`.
   4. Trace the package path: `prepack` runs the build, and the release workflow calls `npm pack --workspace atlas-core` (`.github/workflows/release-atlas-core.yml:323-327,352-360,945-957`). npm's `files: ["dist/"]` rule consequently includes the emitted preview module in the artifact.
9. **Notes:** This is a confirmed package-boundary and maintenance defect, not a claim that normal `atlas-core` execution imports or runs the preview fake. The preview flow is intentionally documented as running from a repository checkout (`surfaces/core-cli/README.md:26-38`), so there is no demonstrated product need to publish this module. The focused package build/pack check could not run to completion in this checkout because the local workspace has no installed `@types/node`/workspace dependencies; the conclusion follows directly from the build include, output, and publication rules. No product code or tests were changed; only this report was added.
