1. **Time & Date:** 2026-08-30T14:58:20Z
2. **Name:** Deployed simulation cleanup can delete a replacement resource with a reused ID
3. **Issue:** Cleanup records only a resource type and ID (plus the run ID prefix), then deletes that pair later without proving that the resource is still the instance created by the run. Core permits an Entity or Object ID to be hard-deleted and created again.
4. **Severity:** S3 (Moderate)
5. **Location:** `simulations/src/server/run-store-cleanup.ts`, `simulations/src/server/run-store.ts`, `simulations/src/server/scenario.ts`; Core resource deletion in `services/core/internal/actions/entity_actions.go` and `services/core/internal/actions/object_actions.go`
6. **Expected:** Deployed cleanup should delete only the exact resource instance created by the run. If the original was deleted and its ID was reused, cleanup should leave the replacement untouched and report that the original instance is no longer present.
7. **Actual:** `createTracked` records `{ type, id }` before the create request and `persistRun` writes that same pair to the deployed cleanup ledger. `cleanupRun` later calls `client.entities.delete(resource.id)` or `client.objects.delete(resource.id)` and treats a successful delete as cleanup of the run resource. It has no creation version, immutable resource token, or conditional-delete precondition. A different authorized actor can delete the original and recreate the same ID; cleanup then deletes the replacement while reporting success.
8. **Reproduction:**
   1. Run this from `simulations/` against the repository fake Core; it uses no live service or external state:
      `node --import tsx --input-type=module -e 'import { RunStore } from "./src/server/run-store.ts"; import { createFakeAtlasCore } from "./test/support/fake-atlas.ts"; const core=createFakeAtlasCore(); const store=new RunStore(core.factory); const scenario={id:"reuse",name:"Reuse",summary:"reuse",inputFields:[],acceptsJson:false,run:async (ctx)=>{await ctx.createEntity({entity_id:ctx.id("asset"),entity_type:"asset"});}}; const started=store.start(scenario,{fields:{}}); while(store.get(started.id)?.status==="running") await Promise.resolve(); const id=store.get(started.id).createdResources[0].id; const other=core.factory(); await other.entities.delete(id); await other.entities.create({entity_id:id,entity_type:"asset",alias:"replacement"}); await store.cleanup(started.id); let replacementAlive=true; try { await other.entities.get(id); } catch { replacementAlive=false; } console.log(JSON.stringify({id,deleted:core.state.deleted,replacementAlive}));'`
   2. The output contains two deletes for the same `entity:<run-id>-asset-...` and `"replacementAlive":false`, demonstrating that cleanup removed the recreated Entity.
   3. The same sequence applies to deployed runs: the simulation README explicitly supports deployed targets and records cleanup candidates, while Core's Entity delete executes `DELETE FROM entities WHERE entity_id = $1` and Object delete executes `DELETE FROM objects WHERE object_id = $1`.
9. **Notes:** This is a source trace plus focused fake-Core reproduction; no deployed target was contacted. The run-ID prefix prevents accidental deletion of unrelated IDs, but it is not an ownership or generation check after deletion and recreation. The smallest durable fix is to add a resource generation/creation-version precondition to cleanup (and a Core conditional-delete API if required), or to make deployed simulation resources un-reusable until their cleanup ledger entry is retired. Add focused tests for Entity and Object delete/recreate races, including an abandoned-run ledger cleanup.
