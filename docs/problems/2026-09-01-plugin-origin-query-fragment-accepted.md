1. **Time & Date:** 2026-09-01T22:45:02-04:00
2. **Name:** Plugin origin validation accepts empty query and fragment suffixes
3. **Issue:** Core accepts operator-edited Plugin endpoint fragments whose `base_url` ends in `?` or `#`, even though the private Plugin contract requires an origin without a query or fragment.
4. **Severity:** S4 (Minor)
5. **Location:** `services/core/internal/config/validation.go:50-53` and `services/core/internal/plugins/client.go:66-130`
6. **Expected:** Loading a Plugin endpoint fragment with `http://plugin:8080?` or `http://plugin:8080#` should fail validation as a non-origin URL. A valid base origin should be used to construct `GET /manifest`, `GET /health`, and `POST /operations/{operation_id}` requests.
7. **Actual:** `url.Parse` records `http://plugin:8080?` with `ForceQuery=true` while leaving `RawQuery` empty, and records `http://plugin:8080#` with all query/fragment fields empty. The validation condition checks `RawQuery` and `Fragment` but not `ForceQuery`, so both values pass and remain in `PluginConfig.BaseURL`. Appending `/manifest` then produces a request URI of `/?/manifest` for the `?` value or `/` with `/manifest` discarded as a fragment for the `#` value, so discovery and health do not reach the Plugin routes.
8. **Reproduction:**
   1. Set a strict endpoint fragment's `base_url` to `http://plugin:8080?`, or to `http://plugin:8080#`.
   2. Load the fragment through `config.Load` with `ATLAS_PLUGIN_CONFIG_DIR` pointing at its directory. `validatePlugins` accepts both values because `url.Parse` returns no error, `Scheme` is `http`, `Host` is non-empty, and `RawQuery`, `Fragment`, and `Path` are empty.
   3. Follow the standard `net/url` parsing semantics: a trailing `?` sets `ForceQuery=true` while leaving `RawQuery` empty, and `url.Parse` removes an empty `#` delimiter without setting `Fragment`. Therefore the predicate at `services/core/internal/config/validation.go:52` is false for both inputs and the values are accepted.
   4. Trace the accepted value through `services/core/internal/plugins/client.go:66-130`: appending `/manifest` yields `http://plugin:8080?/manifest` (request URI `/?/manifest`) or `http://plugin:8080#/manifest` (request URI `/`, with `/manifest` in the fragment), so Core does not address the fixed Plugin routes. The private protocol contract at `docs/atlas-plugins/README.md:260-266` requires a plain origin with no query or fragment.
9. **Notes:** `services/core/internal/config/config.go:74-79` loads endpoint fragments and invokes validation at startup. The first-party verifier only checks that `base_url` is a string (`scripts/plugins.mjs:226-230`), and the catalog generator copies the endpoint JSON unchanged (`scripts/plugins.mjs:260-271`), so operator-edited or packaged fragments can carry these suffixes into Core. Focused check: `(cd services/core && go test ./internal/config)` passed. An ephemeral focused Go probe on this host (Go 1.26.2) confirmed `ForceQuery=true` for `http://plugin:8080?`, an empty parsed `Fragment` for `http://plugin:8080#`, and request URIs `/?/manifest` and `/` after client-style concatenation. No product code or tests were modified. Removing the suffix is a direct workaround; no live Plugin or network was required.
