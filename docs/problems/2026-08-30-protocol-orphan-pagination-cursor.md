# Problem Report

1. **Time & Date:** 2026-08-30T15:07:12Z
2. **Name:** Protocol pagination validators accept orphan continuation cursors
3. **Issue:** The canonical `ChangedSinceResponse` and `FullDatasetResponse` schemas require a cursor when a `has_more*` flag is true, but do not forbid the corresponding cursor when the flag is false. The generated Go and TypeScript predicates therefore accept an envelope with an orphan cursor, while the SDK's HTTP response validators reject it. This leaves generated Protocol validation and SDK boundary validation inconsistent for a legal-looking response supplied by another Core implementation or test double.
4. **Severity:** S4 (Minor)
5. **Location:** `packages/protocol/schema/jsonschema/atlas.schema.json:6-53,768-843`, `packages/protocol/generated/typescript/index.ts:616-621`, `packages/sdk/src/validation.ts:55-74,126-128`, `services/core/internal/actions/query_actions.go:115-215`
6. **Expected:** Each pagination cursor is present exactly when its corresponding `has_more*` flag is true, and generated Protocol validators, SDK inbound validators, and Core's response contract agree on that rule.
7. **Actual:** Go `ValidateChangedSinceResponse` and `ValidateFullDatasetResponse` return no errors for `has_more=false` with `next_cursor` or `next_entity_cursor` present. The generated TypeScript predicates return `true` for the same values. The SDK's `hasValidPagination` returns `false`, so `AtlasClient.queries.changedSince()` and `.full()` reject those responses as invalid. Core's normal query action only assigns cursors inside `if hasMore` branches, so this is primarily an interoperability and contract-validation gap rather than a currently observed Core emission.
8. **Reproduction:**
   1. Run a temporary Go probe from the Protocol module that calls `protocol.ValidateChangedSinceResponse(map[string]any{"events": []any{}, "version": int64(1), "has_more": false, "next_cursor": "orphan"})` and `protocol.ValidateFullDatasetResponse` with `has_more_entities=false` and `next_entity_cursor="orphan"`. Both results are `[]`.
   2. From the repository root, run `node --experimental-strip-types --input-type=module -e 'import { isChangedSinceResponse, isFullDatasetResponse } from "./packages/protocol/generated/typescript/index.ts"; console.log(isChangedSinceResponse({events:[],version:1,has_more:false,next_cursor:"orphan"})); console.log(isFullDatasetResponse({entities:[],tasks:[],objects:[],version:1,has_more_entities:false,has_more_tasks:false,has_more_objects:false,next_entity_cursor:"orphan"}));'`. It prints `true` twice.
   3. Return the same changed-since and full-dataset JSON bodies from an SDK `AtlasClient` fetch stub. `queries.changedSince(0)` and `queries.full()` reject with `Atlas response failed validation` because the SDK's `hasValidPagination` requires the cursor to be undefined when `has_more` is false.
9. **Notes:** The existing Protocol test at `packages/protocol/protocoltest/validators_test.go:388-400` covers a missing cursor when `has_more*` is true but not the inverse. The SDK test at `packages/sdk/test/inbound-validation.test.ts:61-63,90-93` explicitly treats an orphan cursor as malformed. The smallest repair is to add the inverse condition to the canonical schema for each cursor, regenerate all artifacts, and retain the SDK regression cases. No product or test files were changed by this investigation; only this problem report was added.
