# Meshtastic channel is the shared field bus

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Meshtastic channel traffic is visible to every participating Atlas node
3. **Context:** A small Atlas field network needs a combined situational picture. Meshtastic already floods channel broadcasts through the mesh, and every radio holding the channel key can read them. Sending separate copies of useful state to each Asset would consume more airtime while hiding activity that is valuable to the rest of the group.
4. **Decision:** Meshtastic Link uses one private Atlas channel as a shared field bus. Routine state, data requests and responses, Task assignments, cancellation, progress, and outcomes travel on that channel and may be inspected by every Meshtastic Link service. Each message retains an application recipient when only one node may act or reply. Only the addressed Asset may acknowledge or execute its Task. Confirmed Task delivery does not depend on a Link subscription, and observational Task feed traffic cannot invoke a Task handler. Large Object contents and information with no shared situational value are transferred only when explicitly requested or selected.
5. **Alternatives considered:** Per-recipient copies were rejected because they spend airtime without improving the small network's common picture. Private direct messages for all Task and control traffic were rejected because they prevent other Assets from understanding current activity. Separate channels by message family were rejected because the first network benefits more from one coherent picture than from information segregation.
6. **Consequences:** One transmission may update several Shared Pictures. Every channel member can observe operational traffic, and that visibility is intentional for the cooperative, non-contested threat model. Application addressing becomes a safety boundary: passive receipt may update the Shared Picture but must not invoke a foreign Task handler or produce a reply. Missed packets can leave local pictures temporarily different, so the system requires idempotent state application and current-state recovery. Airtime remains shared and must be managed through compact messages, publication selection, and priority rather than per-recipient secrecy.
7. **Location:** `docs/atlas-meshtastic-link/`, `CONTEXT.md`, and the future Meshtastic Link package
8. **Notes:** This decision applies to Atlas application traffic. Meshtastic's own discovery, provisioning, and radio-management exchanges may use other mechanisms when required to join the Atlas channel.
