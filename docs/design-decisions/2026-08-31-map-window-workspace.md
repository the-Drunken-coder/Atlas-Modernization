# Map window workspace

1. **Time & Date:** 2026-08-31 19:40 EDT
2. **Name:** One workspace owns concurrent map-window layout
3. **Context:** The first map results inspector introduced a movable, collapsible window, but each window owning its own position cannot coordinate overlap, z-order, docking, or future concurrent panels. Operators also need a compact way to retain panels without covering the map.
4. **Decision:** The map stage has one `MapWindowWorkspace`. Feature code declares windows with stable identifiers and retains ownership of their content and close behavior. The workspace owns floating position, collapse, activation order, and edge attachment. An expanded attached window remains a full window and stores one normalized position along the top, right, bottom, or left edge. Dragging parallel to that edge moves it continuously. Dragging away detaches it. Collapse parks a floating window at its nearest edge and replaces the full window with a small pull handle at the same normalized position. The handle shows the window icon and a compact count. Hover or keyboard focus reveals the title, current metadata, close action, and required source attribution. Click or Enter restores the full window. Dragging the handle parallel to the edge moves it, while pulling it away restores a floating window. Pointer and keyboard operations use the same state transitions.
5. **Alternatives considered:** The original ordered rail tabs were superseded because their insertion slots limited windows to static positions. A permanently named edge tab was rejected because it covers more map area than the selected pull handle. Retaining the full header while collapsed was rejected because it still reads as a compressed window and leaves too much chrome on the map. Independent window-local state was rejected because it cannot coordinate activation order. A fixed split-pane workbench was rejected because it permanently reduces map area.
6. **Consequences:** New map windows must render inside the workspace and supply a stable ID. Windows with meaningful collapsed identity should also supply a handle icon and compact badge. Workspace layout is currently session-local and resets when the map remounts. Attached windows and collapsed handles keep their relative edge position when the map resizes and clamp only far enough to remain reachable. Multiple windows may occupy the same edge and may overlap; activation order decides which one is in front. Edge attachment uses map area while the window is expanded. Collapsed content is not mounted, but provenance, attribution, and dismissal remain reachable from the handle peek.
