# Meshtastic delivery follows message semantics

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Shared state is best effort while addressed operations require application confirmation
3. **Context:** The shared channel lets every Link service inspect one broadcast, but acknowledging every update would create reply traffic from the entire mesh. Tasks, writes, and requests have different consequences from transient position or Track updates, and radio acceptance does not prove that an Asset application handled a message.
4. **Decision:** Position, telemetry, Tracks, Geofeatures, Object metadata, and other Shared Picture state use best-effort publication without per-listener acknowledgements. Task assignment and cancellation, data requests and responses, explicit resource writes, and Object transfers are confirmed operations addressed to one application recipient. Task delivery does not require a Link subscription. A `tasks_for_asset` subscription is observational picture state and cannot invoke or acknowledge a Task. The Gateway dispatches confirmed Task assignments per Asset in ascending `created_at`, then `task_id`, and waits for application acknowledgement, rejection, or terminal state before delivering the next assignment. A Task is acknowledged only after the assigned Asset application validates and accepts it. Applications do not retransmit overheard messages because Meshtastic owns mesh forwarding. Pending traffic prioritizes safety and cancellation, Task control and outcomes, requests and responses, live Asset and Track state, other resource synchronization, then Object content. Confirmed retries are bounded, with visible failure after exhaustion. Pending confirmed identities remain fenced, and completed outbound identities remain fenced for ten minutes, twice the longest five-minute retry deadline. The Link rejects new confirmed identities when its bounded identity budget is full and wakes blocked capacity waiters when completed identity retention expires. Clients use fresh identities after that horizon and durable Task or Core reconciliation for outcomes that outlive it. The Asset application owns durable Task-ID fencing before physical action, and Core owns authoritative mutation semantics. Initial deadlines are fifteen seconds for safety, cancellation, and Task control, thirty seconds for ordinary requests, responses, and writes, and five minutes for Object content. Any message may fragment. The scheduler reconsiders priority after each chunk. Incomplete best-effort state is discarded without per-listener repair, while confirmed operations may request missing chunks. One Link service emits only one Object-content transfer at a time. Asset software, not Meshtastic Link, owns publication cadence. Under congestion the Link service may replace obsolete unsent best-effort state for the same record, but it never silently replaces or drops a confirmed operation.
5. **Alternatives considered:** Confirming every broadcast was rejected because it creates acknowledgement storms. Treating radio acceptance as Task acknowledgement was rejected because it bypasses the Asset application. Making all traffic best effort was rejected because control and explicit operations need a definite outcome. Unlimited retries were rejected because stale operations must not occupy the channel forever. Application-level forwarding was rejected because it duplicates Meshtastic flooding. Requiring one-packet messages was rejected because packet size is an optimization target rather than an application validity boundary. Letting fragmented traffic reserve the transmitter was rejected because Object content must not block control.
6. **Consequences:** Messages need stable operation identities and explicit recipient semantics even though all channel members may read them. Task feeds and executable Task delivery remain separate. The Gateway and Asset application share responsibility for ordered Task handling. Pending and recently completed identities consume bounded memory; completed identity expiry releases admission capacity while ordinary result retention follows its own cache policy. Reusing an identity after the ten-minute horizon is not a Link guarantee because sender and receiver duplicate histories expire independently. A Link restart may redeliver a semantic operation, so exactly-once physical action is not a Link guarantee. Shared-state convergence depends on Asset-controlled current publication and focused recovery requests rather than perfect delivery. The scheduler must reconsider priority after every chunk, and diagnostics must distinguish radio acceptance, reassembly, application confirmation, replacement under congestion, and semantic failure. Object transfers make progress without monopolizing the Link service. The Link remains reusable across Assets with different publication policies.
