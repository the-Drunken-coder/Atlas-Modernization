# Meshtastic radios use one locally enforced profile

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Every Runtime applies one common Radio profile to its attached radio
3. **Context:** Atlas owns every radio and runs the same Meshtastic Link software behind each one. Gateway and Asset behavior belongs to the companion computer, while remote radio configuration would depend on the same flaky mesh that a configuration change could disrupt.
4. **Decision:** Every supported radio uses one identical Radio profile with no Gateway, Asset, per-device, or per-hardware overlays. Each Runtime reads, converges, and verifies only its locally attached radio before joining and after reconnect. Gateway versus Asset is a software mode outside the radio. Remote radio administration over Meshtastic is a non-goal. The Runtime exposes one validated configuration system through a command-line interface and loopback programmatic API so operators, automation, and AI agents can inspect, change, apply, and verify the desired profile without bypassing radio ownership. Automatic firmware flashing is outside the initial scope.
5. **Alternatives considered:** Role-specific radio profiles were rejected because the radio performs the same mesh function behind either companion-computer role. Hardware overlays were rejected because they create configuration snowflakes; hardware unable to satisfy the common profile is unsupported. Remote administration was rejected because a flaky or partially reconfigured mesh is not a dependable management path. Direct CLI access to the serial port was rejected because it would compete with the running Runtime.
6. **Consequences:** Radio behavior becomes reproducible across the fleet and configuration experiments can be associated with one exact profile. Hardware support requires proving the common settings. Profile distribution happens through companion-computer software or configuration deployment rather than mesh administration. The CLI and programmatic API must share validation and evidence with startup convergence. Device keys, identity, calibration, GPIO, and other undeclared hardware state remain outside the common profile.
7. **Location:** `docs/atlas-meshtastic-link/radio-configuration.md`, `docs/atlas-meshtastic-link/runtime-interface.md`, and the future Meshtastic Link Runtime and CLI
