# Meshtastic Radio contract is generated from Atlas Protocol

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Establish an unoptimized generated Atlas Protocol baseline before compacting the radio representation
3. **Context:** Meshtastic packets are constrained, so a purpose-built compact protocol could save airtime. Designing that protocol first would hide the cost of the ordinary Atlas Protocol, make improvements difficult to quantify, and risk creating a second manually maintained Atlas model. Common Atlas operations may initially need several packets.
4. **Decision:** Atlas Protocol remains the sole source of truth. Meshtastic Link generates a complete Radio contract and asynchronous radio-facing SDK from it, initially preserving Atlas shapes and semantics as ordinary compact UTF-8 JSON without compression or radio-specific field selection. The Link envelope adds only transport identity, addressing, compatibility, sequencing, and fragmentation. Fragmentation remains available to every supported message family, so exceeding one packet is not itself a validation failure. A deterministic faster-than-real-time packet-level simulator uses production serialization and transport code to establish the generated baseline. The baseline has correctness gates but no performance gate because its purpose is to expose the unoptimized cost. Future compact forms must remain generated from Atlas Protocol, decode to the same Atlas operations, and demonstrate improvement in identical benchmark scenarios. One selected encoding revision is used by an operational fleet.
5. **Alternatives considered:** A hand-authored compact radio domain model was rejected because it would become a competing schema before measurements showed which fields cost meaningful airtime. Requiring every operation to fit one packet was rejected because the unoptimized baseline and some legitimate future messages may need fragmentation. Estimating improvement from payload sizes alone was rejected because fragmentation, flooding, loss, queueing, priority, and application confirmation affect the actual result.
6. **Consequences:** The baseline may be inefficient and fragment frequently by design, and missing provisional field latency goals does not invalidate it. Code generation must preserve Atlas Protocol validation and provide a radio-facing operation API without automatically publishing every resource. Radio operations return identities and complete asynchronously; queries retain pagination. Simulation must not bypass production serialization, fragmentation, queueing, receive handling, or Shared Picture updates. It models packet behavior rather than unverified waveform physics. Optimizations require semantic equivalence and reproducible before-and-after evidence. Commands supported on the radio should reference Objects instead of embedding large content, while Object content remains explicitly requested and bounded to 32 KiB initially.
7. **Location:** `packages/protocol`, the future Meshtastic Link package and generator, `docs/atlas-meshtastic-link/wire-protocol.md`, and `docs/atlas-meshtastic-link/simulation-and-benchmarking.md`
