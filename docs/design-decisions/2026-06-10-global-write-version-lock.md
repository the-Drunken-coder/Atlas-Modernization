# Global Write Version Lock

1. **Time & Date:** 2026-06-10 America/New_York (superseded 2026-08-04)
2. **Name:** Transactional counter row for global write versions
3. **Context:** Atlas Core exposes one global version cursor through the feed and `GET /queries/changed-since`. The original implementation combined a PostgreSQL sequence with an advisory lock, but sequence increments survive rollback and forced feed/recovery code to compensate for burned versions.
4. **Decision:** Migration v4 supersedes the sequence/advisory-lock mechanism. Every versioned resource write locks the singleton `atlas_change_clock` row at transaction start, before any per-object advisory lock, upload-intent row, or resource row. It later increments the already-locked clock and appends its complete `atlas_change_events` row in the same transaction as the resource mutation. Non-versioned upload-intent recovery takes the per-object advisory lock before locking its one intent row. Rollback restores the counter and removes the event. The counter row naturally serializes commits, and changed-since reads the event log in that order.
5. **Alternatives considered:** Per-table cursors were rejected because clients would need multiple independent positions. Timestamp cursors were rejected because equal timestamps complicate stable ordering. Keeping the sequence plus skip bookkeeping was rejected once the transactional counter provided a smaller complete design.
6. **Consequences:** Writes remain intentionally serialized from transaction start, but committed versions are contiguous and one durable log drives both push and recovery. The explicit clock → object advisory lock → intent row → resource row hierarchy prevents create/delete and upload-recovery lock inversions. Higher write throughput would require changing the cursor design rather than quietly bypassing the counter row.
7. **Location:** `services/core/internal/actions/write_version.go`, `services/core/internal/actions/change_hook.go`, `services/core/internal/actions/query_actions.go`, `services/core/internal/database/migrations.go`
8. **Notes:** Historical. The live clock and event-log contract is `docs/design-decisions/2026-06-12-change-feed-websocket-fat-events.md` plus `docs/atlas-change-feed/README.md`. Also related to `docs/design-decisions/2026-06-10-resource-write-concurrency.md`.
