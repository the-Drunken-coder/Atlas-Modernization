# Atlas modules follow deployment ownership

1. **Time & Date:** 2026-08-27 EDT
2. **Name:** Organize the Atlas monorepo by deployment role and ownership
3. **Context:** Atlas had reusable packages, hosted software, operator software, field runtimes, and simulations as unrelated root folders. That layout hid dependency direction and encouraged FieldLink, Asset behavior, and Gateway synchronization to grow into one system. Atlas also needs communication methods besides FieldLink, and one logical Asset must remain one independently running Atlas process.
4. **Decision:** Hosted software lives under `services/`, operator applications under `surfaces/`, field-deployed software under `edge/`, reusable contracts and libraries under `packages/`, local scenarios under `simulations/`, and cross-module proof under `tests/`. The concrete roots are `services/core`, `surfaces/command-interface`, `edge/asset`, `edge/gateway`, `packages/protocol`, `packages/sdk`, and `packages/fieldlink`. The `edge/asset` and `edge/gateway` directories contain only role READMEs until their architectures are decided. The previous Asset Runtime package is deleted instead of being treated as the future Asset architecture. FieldLink remains one narrow communication package. It owns MeshCore transport and hardware exercises but not Atlas resources, Core access, Asset execution, or Gateway policy. One logical Asset has one Asset Host. Attached flight controllers, radios, cameras, and sensors remain peripherals. Packages cannot import services, surfaces, or edge modules.
5. **Alternatives considered:** Generic `apps/` and `os/` roots were rejected because they do not state deployment ownership. Keeping every module as an unrelated root folder was rejected because it hides dependency direction. Preserving or relocating the existing Asset Runtime was rejected because its structure should not constrain the replacement Asset architecture. Making FieldLink the edge architecture was rejected because FieldLink is experimental and only one communication method. A shared `edge-protocol` package was rejected because no independent interface and consumers justify it. Copying the old FieldLink bridge into `edge/gateway` was rejected because it combines Gateway and Asset-side policy.
6. **Consequences:** Imports, build paths, Docker contexts, CI, package metadata, and docs follow the new locations. Both `edge/asset` and `edge/gateway` remain documentation-only. Simulations use the SDK directly and do not stand in for Asset host software. The first Asset may run on a laptop and treat an autopilot reached through MAVLink over SiK as a peripheral without committing the repository to an Asset architecture.
7. **Location:** `README.md`, `AGENTS.md`, `CONTEXT.md`, `services/`, `surfaces/`, `edge/`, `packages/`, `simulations/`, `tests/`
