# Atlas Core uses one headless manager and an action-list TUI

1. **Time & Date:** 2026-09-12 08:40 EDT
2. **Name:** Atlas Core uses one headless deployment manager and an action-list TUI
3. **Context:** The current TUI suspends itself while operations run, lets subprocesses own the terminal, and defines contracts imported by the deployment implementation. The approved redesign also changes the future Core-update product policy from mandatory backup acknowledgement to backup-optional recovery evidence.
4. **Decision:** Keep one typed, headless deployment manager inside `surfaces/core-cli`. Direct commands, the Ink/React TUI, and the fixture preview use that manager. Rendering, prompts, and text formatting stay in interface adapters. The TUI uses the approved full-screen action-list design, keeps operations and controlled output inside the interface, serializes mutations, and restores the shell after safe cleanup. The first TUI version retains Plugin installation, status, enable, disable, and logs. Recovery, supervision, and independent Plugin update, rollback, uninstall, catalog refresh, and shared-key rotation remain direct-command-only. The current main-menu filter is removed.

   The released runtime remains unchanged until the implementation issues land. It still requires `ATLAS_CORE_BACKUP_DIR`, validates a paired PostgreSQL and MinIO backup, and records its identity before a Core update. The future Core-update flow removes that prompt and prerequisite. Its transaction journal stores the prior backup identity only when supplied. Receipt-bearing journals retain exact paired-restore recovery. Journals without a receipt reject restored recovery. Before a target Core starts, safe rollback remains available when transaction evidence permits it. After a target Core starts, recovery may retry the exact candidate, move forward to a newly verified compatible target, or perform an explicitly confirmed reset. It never starts the prior Core against migrated or uncertain storage.
5. **Alternatives considered:** Keep suspending Ink around current commands; rejected because it causes the terminal handoff the redesign exists to remove. Publish a separate manager package or service; rejected because both interfaces already ship in one local package. Use OpenTUI; rejected because its native runtime and distribution cost has no demonstrated benefit for this action-list design. Keep backup acknowledgement mandatory; rejected as a product prerequisite, although operators may still create backups and receipt-bearing recovery remains supported. Add mouse support, filtering, background navigation during mutations, or a generic workflow framework; rejected because the first version does not need them.
6. **Consequences:** Operation contracts must return typed results and progress instead of writing terminal UI directly. Child-process output must be captured. Cancellation and terminal loss must wait for safe cleanup. Log controls and precedence are fixed by the canonical specification. Existing ownership, locking, run-intent, compatibility, credential, and recovery protections remain. Operator docs must continue describing current backup-gated behavior until issue #368 changes the runtime, then update in the same implementation change. This decision supersedes prior statements that the TUI design or Plugin menu scope still awaits mock selection. It supersedes mandatory-backup statements only as a future `atlas-core update all` product prerequisite; it does not rewrite current behavior or remove the manual backup and restore runbook.
7. **Location:** `surfaces/core-cli/`, `docs/atlas-core/`, `docs/atlas-plugins/`, and `services/core/docs/DEPLOYMENT_RUNBOOK.md`
8. **Notes:** [GitHub issue #359](https://github.com/the-Drunken-coder/Atlas-Modernization/issues/359) is the canonical specification. [PR #347](https://github.com/the-Drunken-coder/Atlas-Modernization/pull/347) adds the durable design record and static visual references.
