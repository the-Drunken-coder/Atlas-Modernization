# Design Decision

1. **Time & Date:** 2026-06-04T06:31:58Z
2. **Name:** Build Atlas Protocol as a reusable sibling module with canonical generated contracts
3. **Context:** Atlas Protocol is planned as the contract layer for Atlas data, but the repository currently has only the `Atlas_Core/go.mod` module. The planning docs also lived in `Atlas Protocol/`, whose space makes it a poor location for importable Go packages. Atlas Core already has handwritten validation, models, serializers, examples, and docs that duplicate contract rules.
4. **Decision:** Keep `Atlas Protocol/` as planning/reference documentation and create buildable protocol sources under a lower-case sibling module named `atlas_protocol/`. The protocol module path should be `github.com/the-drunken-coder/atlas/atlas_protocol`, with Atlas Core consuming it through a local `replace` during development. Use CUE as the source of truth, pin the first CUE toolchain to `cuelang.org/go/cmd/cue@v0.16.1`, and generate reusable JSON Schema plus Go artifacts from the protocol source. The first implementation slice is the entity JSON blob plus `telemetry` and `geometry` components. Protocol definitions should use canonical field names only rather than carrying Core's legacy aliases.
5. **Alternatives considered:** Put generated Go code under `Atlas_Core/internal/`; rejected because Atlas Protocol is meant to be reusable by systems other than Atlas Core. Put importable packages under `Atlas Protocol/`; rejected because the path is not suitable for Go imports or simple shell tooling. Build protocol versioning first; rejected because this greenfield project prefers full replacements plus generated drift checks during development. Replace every Core validator at once; rejected because a vertical slice gives a safer generator/protocol proof.
6. **Consequences:** The first build must create or flesh out `atlas_protocol/` before Atlas Core imports generated artifacts. Atlas Core will temporarily have a local module replacement. Legacy aliases accepted by handwritten Core validators should be removed or deliberately reclassified as canonical during wiring, not silently preserved in CUE. `go run ./tools/check` in `atlas_protocol/` becomes the protocol freshness gate once implemented.
7. **Location:** `Atlas Protocol/PLANNING.md`, `Atlas Protocol/IMPLEMENTATION_PREP.md`, future `atlas_protocol/`, `Atlas_Core/internal/actions/component_validation.go`, `Atlas_Core/internal/actions/entity_components.go`, `Atlas_Core/internal/actions/geometry_validation.go`
8. **Notes:** This decision works with the existing no-migrations and full-replacement development posture. Protocol drift checks verify generated artifact freshness; they are not compatibility versioning.
