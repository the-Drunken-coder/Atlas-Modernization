# Design Decision

1. **Time & Date:** 2026-06-04T06:31:58Z (updated 2026-06-05)
2. **Name:** Build Atlas Protocol as a reusable sibling module with canonical schema-backed contracts
3. **Context:** Atlas Protocol is planned as the contract layer for Atlas data, but the repository originally had only the `Atlas_Core/go.mod` module. The planning docs originally lived in `Atlas Protocol/`, whose space made it a poor location for importable Go packages and created a confusing second protocol folder at the repository root once `atlas_protocol/` was implemented. Atlas Core already has handwritten validation, models, serializers, examples, and docs that duplicate contract rules.
4. **Decision:** Keep planning/reference documentation under `docs/atlas-protocol/` and buildable protocol sources under a lower-case sibling module named `atlas_protocol`. The protocol module path should be `github.com/the-drunken-coder/atlas/atlas_protocol`, with Atlas Core consuming it through a local `replace` during development. The original bootstrap used CUE, but the current source of truth is draft 2020-12 JSON Schema in `atlas_protocol/schema/jsonschema/atlas.schema.json`. Generate TypeScript, Go validators, and revision metadata from that source; keep the ergonomic Go types authored at the stable package path and structurally parity-check their supported fields and enums against the schema. The first implementation slice is the entity JSON blob plus `telemetry` and `geometry` components. Protocol definitions should use canonical field names only rather than carrying Core's legacy aliases.
5. **Alternatives considered:** Put generated Go code under `Atlas_Core/internal/`; rejected because Atlas Protocol is meant to be reusable by systems other than Atlas Core. Put importable packages under `Atlas Protocol/`; rejected because the path is not suitable for Go imports or simple shell tooling. Keep `Atlas Protocol/` at the repository root after creating `atlas_protocol/`; rejected because it makes the root layout look duplicated. Build protocol versioning first; rejected because this greenfield project prefers full replacements plus generated drift checks during development. Replace every Core validator at once; rejected because a vertical slice gives a safer generator/protocol proof.
6. **Consequences:** The first build must create or flesh out `atlas_protocol/` before Atlas Core imports the reusable package. Atlas Core will temporarily have a local module replacement. Legacy aliases accepted by handwritten Core validators should be removed or deliberately reclassified as canonical during wiring, not silently preserved in the protocol source. `go run ./tools/check` in `atlas_protocol/` is both the generated-artifact freshness gate and the authored-Go/schema parity gate.
7. **Location:** `docs/atlas-protocol/PLANNING.md`, `docs/atlas-protocol/IMPLEMENTATION_PREP.md`, `atlas_protocol/`, `Atlas_Core/internal/actions/component_validation.go`, `Atlas_Core/internal/actions/entity_components.go`
8. **Notes:** Protocol full replacement and drift checks verify generated artifact freshness and supported Go API parity; they are a development posture, not compatibility versioning. Atlas Core's separate PostgreSQL migration ledger exists only to preserve durable production data and does not version the wire protocol.
