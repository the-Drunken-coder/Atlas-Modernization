# Core owns the plugin HTTP interface

1. **Time & Date:** 2026-08-24 22:57 EDT
2. **Name:** Core owns fixed Plugin and Datastream routes
3. **Context:** Atlas needs to add different Plugin capabilities without deploying a new public API for each integration. Allowing each Plugin to register arbitrary routes would fragment authentication, errors, request policy, discovery, and SDK behavior.
4. **Decision:** Atlas Core owns fixed, namespaced Plugin and Datastream routes. Plugins provide implementations behind the Core interface and never expose their own public Atlas routes. The initial route family is `GET /plugins`, `POST /plugins/{plugin_id}/operations/{operation_id}`, `GET /datastreams`, and `GET /datastreams/{plugin_id}/{stream_id}`. Operations are side-effect-free synchronous JSON calls. Core treats input and output as opaque JSON, while the Plugin validates input and owns the result shape. Each Operation descriptor declares the timeout Core enforces, and Core rejects a manifest containing a timeout above its hard maximum. Work that outlives one request uses a Tool Task rather than an asynchronous Operation job. Core maps Operation failures into stable Atlas error categories for rejected input, an unavailable Plugin, timeout, and Plugin failure. It does not proxy the Plugin's HTTP status or raw error body. A Plugin-specific error code and safe diagnostics may appear inside authenticated error details.
5. **Alternatives considered:** Public Plugin-specific APIs were rejected because they recreate the deployment and integration burden the Plugin system exists to remove. Dynamic route registration inside Core was rejected because route behavior, authorization, and documentation would vary by Plugin.
6. **Consequences:** Core owns authentication, authorization, request limits, timeout enforcement, error envelopes, discovery, and route compatibility. Plugin-specific failures do not expand Atlas's top-level error categories or leak private Plugin responses. A Plugin manifest contains its Plugin ID, display name, Operation descriptors with their timeouts, Datastream descriptors, and optional Tool Asset ID. Commands remain in the existing Asset runtime manifest. Configuration, credentials, permissions, protocol versions, and upgrade metadata remain outside the Plugin manifest. Core cannot detect side effects behind opaque Plugin calls, so Plugin tests must enforce the read-only Operation contract. The delivery transport for live Datastreams remains undecided until a real stream establishes its needs.
7. **Location:** `docs/atlas-plugins/`, `atlas_core/cmd/atlas_core/`, `atlas_core/internal/api/`, future Plugin contracts
