# Meshtastic Link does not own Asset publication cadence

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Asset software decides when Asset state and Task progress are published
3. **Context:** Position, Track, telemetry, health, and Task-progress rates materially affect airtime. Putting their schedules in Meshtastic Link would also make the communication method responsible for Asset behavior and assume that unlike Assets should publish alike.
4. **Decision:** The Asset application alone decides when to submit its position, Tracks, telemetry, health, and Task progress for publication. Meshtastic Link validates, queues, prioritizes, fragments, transports, and observes those submitted messages. It does not sample attached systems, detect meaningful state change, invent Asset heartbeats, or impose normal publication cadences. When congestion prevents immediate transmission, the Link service may replace an obsolete unsent best-effort update with the newest submitted state for the same record. Confirmed operations are never silently dropped or replaced.
5. **Alternatives considered:** Fixed Link-owned publication intervals were rejected because they put Asset policy into a reusable communication method. Letting every queued state update transmit eventually was rejected because an obsolete position or progress backlog consumes airtime without improving the Shared Picture. Allowing the Link to drop confirmed operations under congestion was rejected because control and explicit requests require a visible outcome.
6. **Consequences:** Different Asset implementations may choose different publication behavior without changing the Link. Simulation scenarios must provide Asset publication schedules as inputs. The Link still owns congestion policy and exposes replacement and failure evidence. Shared Picture freshness thresholds describe receiver confidence and do not command a source to publish.
7. **Location:** Asset applications, the future Meshtastic Link service, `docs/atlas-meshtastic-link/service-interface.md`, `docs/atlas-meshtastic-link/delivery-and-priority.md`, and `docs/atlas-meshtastic-link/simulation-and-benchmarking.md`
