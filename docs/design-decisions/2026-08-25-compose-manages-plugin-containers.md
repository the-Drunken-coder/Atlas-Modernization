# The deployment orchestrator manages Plugin containers

1. **Time & Date:** 2026-08-25 10:43 EDT
2. **Name:** Docker Compose or the deployment orchestrator starts one container per configured Plugin
3. **Context:** Plugins must fail without taking down Atlas Core, but Atlas should remain one deployed system. Core could manage Docker directly, a shared host could run every Plugin, or the existing deployment orchestrator could manage isolated Plugin containers.
4. **Decision:** The deployment orchestrator starts one trusted container per configured Plugin. The bundled Atlas stack uses Docker Compose. Deployment configuration gives Core the Plugin ID and private base URL, but Core never receives Docker socket access or manages container installation, upgrades, restart policy, resource limits, or shutdown. The first architecture has no separate Plugin Definition and Plugin Instance concepts: one configured Plugin ID maps to one active container.
5. **Alternatives considered:** Core-managed containers were rejected because Docker socket access would give Core broad host authority and add an orchestration system to the application. A shared Plugin host was rejected because one Plugin failure could affect every Plugin and language or dependency conflicts would accumulate in the host.
6. **Consequences:** Plugin images and configuration are part of deployment configuration. Installing, upgrading, or removing a Plugin edits that configuration and restarts the Atlas Compose deployment; Core has no installation API. Deleting a Tool Asset does not remove its Plugin, and the Plugin recreates that Asset at its next startup. Container failure does not terminate Core. A Plugin manages its own concurrent requests and monitored areas instead of Atlas scaling multiple instances. Development scratch data may be cleared under the existing destructive development workflow, while production restart remains durable. Untrusted third-party images, horizontal Plugin scaling, and a Plugin marketplace remain outside the first version.
7. **Location:** `docs/atlas-plugins/`, future Docker Compose Plugin configuration
