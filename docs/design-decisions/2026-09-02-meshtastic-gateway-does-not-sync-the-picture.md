# Meshtastic Gateway does not sync the Shared Picture

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** The Gateway submits intentional Field reports rather than copying its Shared Picture into Core
3. **Context:** Every Link service builds an ephemeral Shared Picture from both addressed and passively heard channel traffic. The Gateway also holds a picture, but Atlas Core is a different system with durable resources, validation, versions, and authoritative Task state. Treating every picture update as a Core write would turn passive duplicates and Core-originated broadcasts into feedback loops.
4. **Decision:** The Gateway processes valid field-originated Atlas reports and operations once through typed Atlas SDK operations. Telemetry, Tracks, Asset-created Geofeatures, Task lifecycle reports, and supported explicit resource operations may update Core. Passive duplicates, restored picture entries, and the Gateway's own Core-originated broadcasts do not. Core remains final for every Task. A field Task report may appear immediately in the Shared Picture as awaiting confirmation; Core acceptance confirms it, while rejection replaces it with authoritative state and is returned to the originating Asset.
5. **Alternatives considered:** Synchronizing the entire Shared Picture was rejected because the picture is incomplete, ephemeral, and contains passively duplicated state. Waiting for Core before exposing field Task progress was rejected because it hides useful live activity from the mesh. Allowing field state to override Core Task state was rejected because it would create competing Task authorities. Silently dropping rejected operations was rejected because the originating Asset and operator need to understand the divergence.
6. **Consequences:** Field reports require a role-tagged source Link node, an Asset and Atlas Runtime ID when applicable, provenance, stable semantic identities, and typed Core mappings. The Gateway must distinguish direct field origin from Gateway feeds and passive copies. Core and the Shared Picture may temporarily disagree, and picture records must expose confirmation state. Resource-specific operations remain explicit rather than becoming a generic picture-to-Core synchronization engine.
7. **Location:** `docs/atlas-meshtastic-link/gateway-core-bridge.md`, `docs/atlas-meshtastic-link/shared-picture.md`, and the future Gateway application
