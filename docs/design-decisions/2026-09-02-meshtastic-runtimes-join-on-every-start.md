# Meshtastic Runtimes join on every start

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Runtime membership and Shared Picture state do not persist across starts
3. **Context:** Meshtastic Link needs dynamic field joining, may change its authentication scheme, and operates with exactly one Gateway. Reusing previous membership would require rules for credential validity, missed membership changes, restored picture freshness, and recovery after partial shutdown.
4. **Decision:** The Gateway is the only join authority and uses a replaceable authentication policy. Every Meshtastic Link Runtime performs discovery, authentication, and joining whenever it starts, even if it joined previously. Runtime membership, the Shared Picture, pending Link operations, and transmission queues do not persist. The old Runtime fails pending local callers. The machine retains its stable Atlas Asset ID independently of the radio and Runtime lifecycle. After joining, the replacement Runtime reports ready when its local service interface is operational and builds an empty Shared Picture from live channel traffic without requesting a baseline dump. Authoritative Asset or Core state decides whether failed work must be resubmitted or reconciled.
5. **Alternatives considered:** Persisting membership and reconnecting directly was rejected because it creates a second startup path and requires validity and recovery rules. Peer-sponsored joining was rejected because the system has one Gateway and does not need distributed admission. Using the radio node identity as the Asset identity was rejected because radio replacement must not create a new Atlas Asset. Restoring the prior Shared Picture was rejected because stale cached state conflicts with the live-listening model.
6. **Consequences:** Startup has one predictable path and authentication can change behind one seam. A Runtime that starts while the Gateway is unavailable cannot participate until the Gateway returns, although members that remain running continue exchanging state. Every start consumes discovery and joining airtime. Local callers observe failure rather than an operation silently surviving into a new Runtime. Stable Atlas and operation identities support deliberate reconciliation. A newly joined Runtime begins with incomplete knowledge and should normally build a useful current picture within thirty seconds in the initial five-radio network; this is an acceptance target rather than a readiness guarantee.
