# Meshtastic Runtime is a local service

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** One Runtime owns the radio and exposes a language-neutral local interface
3. **Context:** Asset autonomy needs real-time access to the Shared Picture and the ability to request or publish data without blocking on a low-bandwidth radio. Embedding radio ownership in every local program would create competing connections, duplicate state, and language-specific integrations.
4. **Decision:** Each participating machine runs one Meshtastic Link Runtime as a long-running service. It exclusively owns the radio and Shared Picture and serves multiple Runtime clients through a loopback-only JSON interface. Clients read a current in-memory picture snapshot and follow live server-to-client events. The picture is read-only. Publishing state, reporting Task progress, requesting data, and managing subscriptions use explicit operations. Requests return an ID and complete asynchronously. Requests requiring an unavailable Gateway fail promptly rather than remaining queued. Raw packets and transport internals stay behind a diagnostic interface.
5. **Alternatives considered:** A library embedded separately in each Asset process was rejected because it permits competing radio owners and separate pictures. A file such as `world_state.json` was rejected because polling and whole-file replacement are poor real-time interfaces. Giving clients raw packets was rejected because it leaks transport internals into Asset behavior. Blocking local calls until radio completion was rejected because radio latency must not stall autonomous software.
6. **Consequences:** The Runtime becomes a deployable process with a local lifecycle and interface contract. Local clients may use different programming languages without duplicating radio behavior. The service must aggregate local subscription demand, preserve request correlation, expose freshness, and recover cleanly from client disconnects. The initial implementation should prefer ordinary loopback HTTP and server-sent events unless a measured requirement demands a different local transport.
7. **Location:** `docs/atlas-meshtastic-link/runtime-interface.md`, `CONTEXT.md`, and the future Meshtastic Link Runtime package
