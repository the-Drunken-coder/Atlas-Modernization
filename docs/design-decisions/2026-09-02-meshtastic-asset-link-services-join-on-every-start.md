# Asset Link services join on every start

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Asset membership and Shared Picture state do not persist across Link service starts
3. **Context:** Meshtastic Link needs dynamic field joining, may change its authentication scheme, and operates with exactly one Gateway. Radio settings survive a companion service restart, while the Gateway cannot discover and join through itself. Regenerating private-channel material on Gateway restart would also disconnect every Asset that remained running.
4. **Decision:** The Gateway is the only join authority and uses a replaceable authentication policy. The Gateway deployment creates one durable Link membership record and its service loads that record directly on every start. It never joins through itself or changes the private-channel key during an ordinary restart. Every Asset-mode Link service clears or disables old private-channel material, then performs discovery, public-key-encrypted authentication, and joining whenever it starts. Protected joining requires Meshtastic 2.7.15 or a later tested release and refuses shared-channel-key fallback. Each accepted service instance receives an increasing Gateway-issued source generation. Asset service membership, the Shared Picture, pending Link operations, duplicate fences, and transmission queues do not persist. The machine retains its stable Atlas Asset ID. The replacement service builds an empty Shared Picture from live channel traffic without requesting a baseline dump.
5. **Alternatives considered:** Letting the Gateway join through itself was rejected because no authority exists before Gateway bootstrap. Recreating membership on Gateway restart was rejected because it would strand running members. Reusing Asset radio membership without admission was rejected because it creates a second Asset startup path and bypasses the current authentication policy. Peer-sponsored joining was rejected because the system has one Gateway and does not need distributed admission. Restoring the prior Shared Picture was rejected because stale cached state conflicts with the live-listening model.
6. **Consequences:** Gateway membership and source-generation counters are durable even though Asset service state is not. A restarting Gateway resumes the existing private channel. An Asset service that starts while the Gateway is unavailable cannot participate until the Gateway returns, although Asset services that remain running continue exchanging state. A higher accepted source generation permanently retires delayed traffic from lower generations. Each Asset start consumes discovery and joining airtime and begins with incomplete knowledge. The picture should normally become useful within thirty seconds in the initial five-radio network, but that is an acceptance target rather than a readiness guarantee.
