# Meshtastic development is bandwidth-first

1. **Time and date:** 2026-09-02, America/New_York
2. **Name:** Application design targets short, high-capacity modem presets before optimizing range
3. **Context:** The first system uses Heltec V3 development radios, while later field hardware is expected to provide more transmit power. More capable hardware can improve range but does not increase the bandwidth of a selected modem preset. Designing around a slow long-range preset could unnecessarily constrain the application before its actual traffic is measured.
4. **Decision:** Meshtastic Link development uses `SHORT_FAST` as the normal US Radio profile. Message shapes, publication behavior, and acceptance tests assume its high-capacity short-range envelope rather than `LONG_FAST`. `SHORT_TURBO` is an explicitly selected maximum-capacity experiment, not a requirement hidden in the normal design. Higher-power radios retain the same application design and modem bandwidth. If the system has unused capacity, later profiles may trade bandwidth for more range; if it lacks capacity, experiments may move toward the fastest legal supported preset.
5. **Alternatives considered:** Starting with `LONG_FAST` was rejected because its lower capacity would shape the application around range that later hardware may provide independently. Hard-coding `SHORT_TURBO` into the protocol was rejected because the wire design should not depend on one modem profile and the preset may change after measurement. Using different presets per radio was rejected because every radio must share one common profile to communicate reliably.
6. **Consequences:** Early range tests on Heltec V3 hardware do not define the final field range. Airtime and convergence tests must record the exact preset. The application must meet its normal traffic target on `SHORT_FAST`; Turbo provides measured headroom rather than masking an over-budget design. The application must still behave correctly when a slower profile is selected. Region legality, hardware support, and actual range remain profile validation and field-test concerns.
7. **Location:** `docs/atlas-meshtastic-link/radio-configuration.md`, the common Radio profile, and future radio simulations and field evidence
